## 第一章 综合项目的进展情况

### 1.1 针对工程问题的方案设计

本项目承接综设 I 的需求分析与数据库设计，在综设 II 阶段需解决以下复杂工程问题，并给出相应方案。

#### （1）多数据源融合

**问题描述：** 风控决策不能仅依赖库内用户信用分，还需融合征信、运营商等外部特征，且各数据源接口形态不一。

**方案设计：**
- 采用**适配器模式**，定义 `ExternalDataSourceAdapter` 统一接口；
- 由 `ExternalDataOrchestrator` 并发拉取各数据源，汇总为 `FeatureSnapshot`；
- 爬取结果写入 `t_external_data_cache`，适配器优先读缓存，无缓存时算法兜底；
- 定时任务 `DataCrawlerScheduler` + 管理端手动触发接口保证数据 freshness。

#### （2）评分卡风控机制

**问题描述：** 任务书要求体现「模型化」风控，且结果需可解释、可答辩演示。

**方案比选：**

| 方案 | 说明 | 结论 |
|------|------|------|
| 纯规则引擎 | IF-ELSE 阈值判断 | 实现快，但难以体现评分卡 |
| **评分卡 + 规则链** | 分箱计分 + 规则补充 | **选用** |
| 机器学习模型 | XGBoost 等 | 样本不足，v1 不采用 |

**选定方案：** `SimpleScoringCardEngine` 对信用分、贷款金额、征信逾期次数、运营商在网时长等特征分箱计分，阈值 40 分通过；`ScoringCardRiskEvaluator`、`BasicRiskRuleEvaluator`、`ExternalDataRiskEvaluator` 组成规则链，结果写入 `risk_reports`。

#### （3）借款端与管理端技术选型

| 端 | 方案 | 结论 |
|----|------|------|
| 管理端 | Vue3 + Element Plus + ECharts | 选用，替代 legacy 静态页 |
| 借款端 | uni-app（Android） | 选用，一套代码可出 H5/APK |
| 后端 | Spring Boot 3.2 + JPA + JWT | 选用，与课程技术栈一致 |
| 部署 | Docker Compose + Nginx 同源 | 选用，便于答辩演示 |

#### （4）系统总体架构

```
借款端(uni-app) ──┐
                  ├── REST API ── Spring Boot ──┬── MySQL
管理端(Vue3)   ──┘                              ├── Redis
                                                 └── 爬取模块 → 外部数据缓存
                                                          ↓
                                                 特征融合 → 评分卡 → 风控报告
```

详细设计见 `docs/综设II-总体设计说明书.md`。

### 1.2 针对工程问题的推理分析

#### （1）为何采用评分卡而非黑盒模型

个贷风控在课程场景下强调**可解释性**与**工程可落地性**。评分卡将特征映射为分值，便于在答辩中展示「某用户因逾期次数扣 20 分」等逻辑；规则链可叠加硬性拒绝条件。相较机器学习，评分卡不依赖大量标注样本，与当前数据规模匹配。

#### （2）为何爬取 + 缓存而非直连生产 API

真实征信/运营商接口需资质与 VPN，课程环境不可行。推理路径为：**演示 HTML 模拟外部页面 → Jsoup 解析 → 入库缓存 → 适配器消费**，既满足「数据爬取开发」任务要求，又为后续替换真实 API 预留 `ExternalDataSourceAdapter` 扩展点。

#### （3）业务流程与风控触发时机

用户提交贷款申请时同步触发风控，避免「先审后评」导致管理端信息滞后。推理依据：申请是风控的 natural trigger；审批员需在同屏看到 `riskAssessment` 再作决策。审批通过后自动生成合同，签署完成后方可放款，保证状态机合法流转。

#### （4）配置外置与安全

JWT 密钥、数据库密码等通过 `${ENV:default}` 外置，Docker 部署时注入 `.env`，推理依据：开发便利与生产安全需分离；避免敏感信息进入版本库。

## 第二章 存在问题与解决方案

### 2.1 存在的主要问题

#### （1）技术实现层面

| 问题 | 表现 |
|------|------|
| CORS 配置冲突 | 多处 CORS 配置导致前端预检失败 |
| JWT 密钥长度 | 短密钥导致 `Keys.hmacShaKeyFor` 签名失败 |
| 事务未回滚 | 部分异常被捕获后未抛出，数据不一致 |
| Redis 依赖 | 本地未启 Redis 时影响启动或验证码 |
| 前后端字段不一致 | 部分 DTO 字段命名与前端期望不符 |

#### （2）业务与进度层面

| 问题 | 表现 |
|------|------|
| Android APK 未产出 | 页面完成但未云打包，答辩演示风险 |
| 爬取为演示级 | 非真实征信 API，需在文档中说明边界 |
| 集成测试不足 | 以单测和手工联调为主，MockMvc 覆盖少 |
| 文档与代码不同步 | 早期完成度报告未反映合同/爬虫等进展 |

#### （3）团队协作层面

- 前后端接口变更未及时同步 Swagger；
- 成员对评分卡分箱规则理解不一致，曾出现阈值演示与文档不符。

---

### 2.2 解决方案

#### （1）已实施的技术方案

| 问题 | 解决方案 |
|------|----------|
| CORS | 统一 `CorsConfig` + Security 引用，放行 OPTIONS |
| JWT 密钥 | 不足 32 字节时 SHA-256 扩展 |
| 事务 | `@Transactional(rollbackFor = Exception.class)`，异常向上抛出 |
| Redis | Docker 部署自带 Redis；开发环境可选降级 |
| 字段不一致 | 以 Swagger 为准，前端 api 层统一映射 |

#### （2）业务与进度应对

| 问题 | 解决方案 |
|------|----------|
| APK | 按 `README-Android打包.md` 使用 HBuilderX 云打包；答辩备用 H5 + 模拟器 |
| 爬取边界 | 总体设计中明确「演示 HTML + 可扩展适配器」；答辩说明替换路径 |
| 测试 | 补充评分卡、爬取、合同单测；编写 `综设II-测试报告.md` |
| 文档 | 更新四套 SE 文档与完成度报告 |

#### （3）协作改进

- 接口变更必须更新 Swagger 并在群内通知；
- 风控规则以 `application.properties` 中 `risk.scoring-card.*` 为唯一配置源；
- 每周例会核对里程碑与 Git 分支合并情况。
