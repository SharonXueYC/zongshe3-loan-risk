## 第一章 综合项目的进展情况

### 1.1 针对工程问题的方案设计

本项目以综设 I 成果为基础，围绕「**多数据源融合 + 评分卡风控 + 全链路个贷业务**」展开。经需求分析、方案比选与迭代开发，形成如下最终方案。

#### （1）复杂工程问题分解

| 工程问题 | 设计思路 | 核心模块 |
|----------|----------|----------|
| 多数据源异构接入 | 适配器 + 编排器 + 统一特征快照 | `ExternalDataOrchestrator` |
| 外部数据获取 | HTML 爬取 → 缓存 → 适配器消费 | `DataCrawlerService` |
| 风控模型选择 | 评分卡为主、规则链为辅 | `SimpleScoringCardEngine` |
| 业务状态一致性 | 状态机 + 声明式事务 | `ContractServiceImpl` 等 |
| 多端协同 | REST + JWT + Nginx 同源 | `deploy/nginx/nginx.conf` |

#### （2）架构方案

系统采用**前后端分离、三层架构**：

- **表现层：** uni-app 借款 APP（Android/H5）、Vue3 管理 Web；
- **业务层：** Spring Boot 提供 REST API，含用户、贷款、合同、还款、风控、爬取、统计等子系统；
- **数据层：** MySQL 持久化，Redis 辅助，爬取结果缓存表 `t_external_data_cache`。

#### （3）风控流程方案（最终选定）

```
申请提交 → 构建 FeatureContext → 并发拉取外部数据（读爬取缓存）
        → SimpleScoringCardEngine 计分 → 规则链评估
        → 写入 risk_reports → 返回管理端/APP
```

**比选结论：** 放弃 v1 阶段机器学习方案，选用评分卡 + 规则链，兼顾任务书「评分卡机制」要求与答辩可解释性。

#### （4）部署方案

Docker Compose 一键启动 MySQL、Redis、Backend、Nginx；Nginx 将 `/`（用户 H5）、`/admin/`（管理端）、`/api/`（后端）同源代理，解决移动端跨域与生产模拟需求。

### 1.2 针对工程问题的推理分析

#### （1）多数据源融合的推理

风控特征来自三类来源：**库内**（用户信用分、申请金额）、**征信爬取**（逾期次数、查询次数）、**运营商爬取**（在网时长）。若各源直接耦合在 Service 中，扩展新数据源需改动核心逻辑。推理结论：引入 `FeatureSnapshot` 作为融合中间表示，新数据源仅需新增 Adapter，符合开闭原则。

#### （2）爬取与缓存的推理

外部页面更新频率低于实时 API，但课程演示需可控数据。推理采用「定时爬取 + TTL 缓存」：降低运行时对外部文件的依赖，且管理端可手动 `POST /api/admin/crawler/run` 刷新，便于答辩现场演示「爬取 → 风控分值变化」。

#### （3）合同—放款闭环的推理

任务书要求完整业务链。推理路径：审批通过 → 自动生成合同 → 用户/管理员签署 → 放款 → 生成还款计划。每一步状态变更均有校验（如未签署不可放款），避免跳跃式操作导致账务不一致。

#### （4）测试策略的推理

全链路 E2E 成本高，推理优先对**高业务风险模块**编写单元测试：合同签署/放款、审批触合同、评分卡边界、爬取解析。集成测试以手工用例 + Docker 部署验证补充，在课程周期内性价比最高。

## 第二章 存在问题与解决方案

### 2.1 存在的主要问题

#### （1）开发过程中暴露的问题

| 序号 | 问题 | 影响 |
|------|------|------|
| 1 | CORS 多处配置冲突 | 前端无法调用 API |
| 2 | JWT 密钥长度不足 | 令牌生成失败 |
| 3 | Spring Security 拦截静态资源 | 管理页 403 |
| 4 | 事务异常被吞掉 | 注册等操作数据不一致 |
| 5 | Redis 未启动 | 本地环境启动/验证码异常 |
| 6 | 参数校验错误信息不详细 | 前端难以定位字段 |
| 7 | legacy 静态页与 Vue 双轨维护 | 功能重复、易不一致 |
| 8 | 合同/放款接口后期才闭环 | 中期演示链路不完整 |

#### （2）项目边界与局限

| 序号 | 问题 | 说明 |
|------|------|------|
| 1 | 爬取源为演示 HTML | 非真实征信/运营商生产接口 |
| 2 | Android APK 依赖云打包 | 页面已完成，安装包需 HBuilderX 生成 |
| 3 | 集成测试自动化不足 | MockMvc / Testcontainers 覆盖有限 |
| 4 | 部分 UI 为演示级 | 人脸、银行卡等未接真实第三方 |
| 5 | HTTPS 未配置 | 课程 Docker 环境为 HTTP |

---

### 2.2 解决方案

#### （1）技术问题已解决项

| 问题 | 解决措施 | 效果 |
|------|----------|------|
| CORS | 统一 CorsConfig，Security 引用并放行 OPTIONS | 三端联调正常 |
| JWT | SHA-256 扩展短密钥至 32 字节 | 令牌稳定生成 |
| 静态资源 | Security 放行规则 + WebConfig 资源映射 | 页面可访问 |
| 事务 | rollbackFor + 业务异常向上抛出 | 数据一致性恢复 |
| Redis | Docker 内置 Redis；开发可选降级 | 部署环境稳定 |
| 校验错误 | GlobalExceptionHandler 返回字段级 errors | 前端友好提示 |
| 双轨前端 | 删除 legacy-static，统一 Vue 管理端 | 维护成本降低 |
| 合同闭环 | ContractServiceImpl 全链路 + 单测 | 申贷到放款可演示 |

#### （2）边界问题的应对策略

| 问题 | 策略 |
|------|------|
| 演示级爬取 | 文档明确边界；Adapter 接口预留真实 API 实现；答辩演示「爬取 → 分值变化」 |
| APK 打包 | 提供 `README-Android打包.md`；答辩备用 H5 + 模拟器 |
| 测试不足 | 核心 Service 13 单测 + 8 项手工用例；测试报告归档 |
| 演示 UI | 总结报告中说明 v1 范围；后续版本接 SDK |
| HTTP | 课程环境可接受；生产扩展时 Nginx 配置 SSL |

#### （3）过程改进经验

1. **接口先行：** Swagger 冻结后再并行前端/APP，减少返工；  
2. **小步提交：** 合同、爬取等模块独立分支合并，降低集成风险；  
3. **配置单一来源：** 评分卡阈值、爬虫 URL 集中在 `application.properties`；  
4. **文档与代码同步：** 每完成里程碑更新完成度报告与 SE 文档。
