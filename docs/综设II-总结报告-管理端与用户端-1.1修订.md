## 1.1.1 管理员前端（修订全文）

管理员前端主要面向后台管理人员，承担贷款申请审核、用户信息查看、风险结果展示、合同信息管理、贷款产品维护以及系统运行数据统计等功能。相比普通用户端，管理员端不仅需要完成页面展示，还需要围绕贷款业务流程，对不同状态的数据进行管理和处理。因此，在开发过程中，我没有单纯地从“做页面”的角度出发，而是先分析管理员在实际业务操作中可能遇到的问题，再根据问题设计对应的前端方案，最后通过具体页面和功能实现落地。

本模块采用 **Vue3 + Vite + ECharts + 原生 fetch** 的技术方案进行开发。其中，Vue3 用于搭建单页面应用和页面组件；**表格、表单、按钮、弹窗等界面元素在 Dashboard.vue 中以自定义 HTML 结构与 CSS 样式实现，未引入 Element Plus 等 UI 组件库**；ECharts 用于实现贷款数据、风险分布、审批情况等可视化展示；**网络请求在 api/client.js、api/admin.js 中基于 fetch 封装**，自动携带 Bearer Token。整体页面采用后台管理系统常见的布局方式，即**顶部导航栏、**左侧菜单栏加右侧内容区。左侧菜单包括**控制台、用户管理、贷款管理、产品管理、还款计划、合同管理、数据统计、系统设置**等模块，**风控通过/未通过、评分卡分数、拒绝原因等在贷款管理列表及详情弹窗中集中展示，未单独设立「风控结果展示」菜单页**；右侧内容区根据菜单切换显示对应页面。这样的结构能够让管理员快速找到对应功能，也方便后期继续扩展新的业务模块。

在具体设计与实现过程中，管理员前端主要解决了以下几个复杂工程问题。

**问题一：贷款业务流程较长，页面之间容易割裂**

**问题描述：**
个人贷款业务本身不是一个简单的单页面操作，而是包含“用户提交申请、系统进行风控评估、管理员审核、生成合同、后续放款或归档”等多个环节。在前期设计页面时，如果只按照功能模块分别开发，比如单独做申请列表、单独做合同页面、**而把风控信息与申请完全割裂**，就容易导致各个页面之间缺少业务联系。管理员在查看某一条贷款申请时，可能需要在多个页面之间来回切换，才能判断这笔贷款目前处于什么阶段、是否已经完成风控、是否可以进入下一步审核。这样会降低操作效率，也不符合真实后台系统的使用习惯。

**设计思路：**
针对这一问题，我在管理员前端设计中将贷款业务流程作为主线，把“申请提交—风控评估—人工审核—合同处理—完成归档”作为统一流程进行展示。**在贷款管理模块中，列表页展示审核状态与风控结果摘要，详情弹窗中集中展示风控评估、评分卡分数及审批操作入口**，使管理员在处理贷款申请时可以先从整体上了解当前业务进度，再进行对应操作。

**问题三：前后端数据交互复杂，接口管理容易混乱**

**问题描述：**
管理员前端需要和后端频繁交互，包括获取贷款申请列表、查看申请详情、提交审核结果、获取风控信息、更新产品信息、查询合同状态等。如果每个页面都直接写接口请求代码，会导致代码重复较多，接口路径分散在不同文件中，后期维护时很不方便。一旦后端接口路径或参数发生变化，就需要在多个页面中逐个修改，容易出错。

**设计思路：**
针对接口调用分散的问题，我采用统一封装接口的方式，**将 api/client.js 作为通用请求层、api/admin.js 按业务封装各模块接口方法**，页面通过 import 调用这些方法并处理返回结果。这样可以降低页面代码复杂度，也方便后期维护。

**问题五：风控结果不够直观，管理员难以快速判断风险**

**问题描述：**
个人贷款系统的重点之一是风险控制。对于管理员来说，只看到普通文本形式的风控结果并不直观，尤其是在面对大量贷款申请时，很难快速判断哪些申请属于高风险、哪些属于低风险。如果风险信息只是简单显示为文字，可能会影响审核效率。

**设计思路：**
针对风控结果展示不直观的问题，我在贷款列表与详情中**通过 risk-badge 颜色标签、风险等级标签及未通过行高亮等方式**展示风控结果，**控制台与数据统计页辅以 ECharts 图表反映申请趋势与状态分布**，使管理员能够快速识别重点关注对象。

**问题七：页面模块较多，后期维护和扩展存在困难**

**问题描述：**
管理员端包含控制台、贷款管理、合同管理、产品管理**、用户管理、还款计划、数据统计、系统设置**等多个模块。如果每个页面都单独写完整代码，容易造成结构混乱，也不利于后期新增功能。例如后期如果要新增**其他业务**模块，就需要考虑是否能快速接入原有系统结构。

**设计思路：**
针对系统可维护性问题，我**以 Dashboard.vue 为核心，通过 currentPage 变量切换各功能区块，将登录页与主控制台拆分为 Login.vue 与 Dashboard.vue 两个组件**；公共请求逻辑抽取至 api 目录，**还款计划等模块已按同一结构接入左侧菜单**。新增模块时可在 Dashboard 中扩展菜单项与对应内容区，保持统一布局。

**问题八：用户操作需要及时反馈，否则容易产生误解**

**问题描述：**
在后台管理系统中，管理员经常需要进行查询、提交、审核、删除、修改等操作。如果页面没有及时反馈，用户可能不知道操作是否成功，也可能因为等待时间过长而重复点击按钮。例如审核贷款申请时，如果点击“通过”后页面没有变化，管理员可能会再次点击，造成重复请求。

**设计思路：**
针对操作反馈不足的问题，我在页面设计中**通过 window.confirm 进行审核、放款等关键操作确认，通过 alert 提示成功或失败信息，并在提交过程中配合按钮状态控制**，让管理员在每一步操作后都能得到明确反馈。**后续可进一步统一 Loading 与 Toast 组件。**

## 1.1.2 用户端前端（修订全文）

在本项目中，我主要负责互联网个人贷款风控系统的用户端前端部分。用户端面向普通个人贷款用户，用于完成从注册登录、贷款申请到还款管理的全流程操作。

用户端前端需支撑以下核心业务场景：

1. **身份认证与账户管理：** 实现用户登录（密码/验证码双模式）、两步注册、Token持久化、权限管控、**人脸验证（H5 演示模拟流程，未接入真实摄像头 SDK）**、个人信息管理。
2. **核心业务流程管理：** 贷款申请（金额输入+快捷选择+实时计算器）、额度查询与提额（信誉分环形进度条+增信资料提交）、还款管理（待还计划全额/部分还款+还款记录筛选）、借款记录查看（进度条可视化）。
3. **通用适配与体验要求：** 多端适配（Flexbox+媒体查询）、UI规范（CSS变量统一主题色）、**性能与体验（信誉分环采用 CSS transition 过渡动画；各页内置 showToast；关键操作跳转确认页）**、安全保障（敏感操作二次确认+**登录态校验 ensureSessionOrRedirect，访问 /?logout=1 可清除登录态**）。

**方案设计**

采用原生HTML5 + CSS3 + JavaScript（ES6+）技术栈，MPA架构。CSS使用Flexbox布局配合媒体查询实现响应式适配；**公共脚本集中在 js/api-config.js、js/user-session.js，各业务页面为独立 html 文件并按需编写页面内逻辑**；网络请求**以 fetch API 为主**，**在 user-session.js 中封装 apiRequest 等方法，自动携带 Token；401 等异常主要依靠 ensureSessionOrRedirect 与各页错误提示处理，当前尚未实现带 AbortController 的全局超时封装**。

功能模块划分：登录注册模块（密码/验证码登录+两步注册）、**首页（main-home.html，可借额度展示+功能菜单网格+快捷操作列表）**、借款申请模块（金额输入+快捷选择+实时计算器）、额度查询模块（环形进度条+增信提额）、还款管理模块（**待还计划与还款记录两个同页功能区块**+筛选）、银行卡管理模块（绑卡+列表展示+本地缓存）、借款记录模块（状态标签+进度条）、人脸验证与额度评估模块。

多页面数据同步采用localStorage + URL参数 + **部分页面 pageshow 事件监听**方案。注册采用两步模式（第一步拦截无效手机号）；借款采用实时计算（决策前了解成本）；还款跳转确认页二次确认（保障资金安全）。

**功能模块设计：**

**登录注册模块：** 登录支持密码登录和验证码登录两种方式；注册采用两步模式（先验证手机号再设置密码），可在第一步拦截无效手机号，提升注册成功率。

**首页：** 顶部展示可借额度（实时从后端获取），中部为功能菜单网格，**下方为快捷操作列表（通过页面跳转进入各功能，非底部 Tab 导航）**。

**借款申请模块：** 支持金额输入（含快捷金额选择）、期限选择、还款方式选择，集成实时还款计算器——用户调整参数时立即更新月供和总利息，让用户在决策前了解借款成本。**提交成功后跳转 loan-records.html?submitted=1 查看记录与进度。**

**额度查询与提额模块：** 展示信誉分环形进度条和构成明细，用户可通过提交增信资料主动提额。**环形进度条通过 SVG stroke-dashoffset 配合 CSS transition 实现动画。**

**还款管理模块：** 分为"待还计划"（支持全额/部分还款，跳转确认页二次确认）和"还款记录"（支持按日期、金额筛选），**两者为同一页面内上下卡片布局，非 Tab 切换**。

**借款记录模块：** 展示历史申请列表，以进度条直观展示审核进度（已提交→风控评估→人工审核→结果）。**状态文案优先使用后端返回的 statusText。**

**人脸验证与额度评估模块：** 人脸验证**为 H5 演示模拟流程（眨眼→点头→保持不动）**；**额度评估页（review-progress.html）**基于真实后端接口串行调用，每步完成后自动进入下一步。

**多页面数据同步方案：** 采用localStorage + URL参数 + pageshow事件监听，保证MPA架构下的数据一致性。

**流程设计优选：** 注册采用两步模式（提升成功率），借款采用实时计算（让用户决策前了解成本），还款跳转确认页（保障资金安全）。

**创新设计：** 实时还款计算器；增信资料自主提额；进度条可视化；**信誉分环形进度条 CSS 过渡动画**。

总体来说，用户端前端围绕"移动端好用、操作流畅、反馈及时"展开，通过原生技术栈和完善的数据同步机制，构建了一套完整的移动端贷款全流程解决方案。
