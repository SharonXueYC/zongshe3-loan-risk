## 项目概述

**项目名称：** 综合贷款管理系统（ZongShe Loan Management System）

**项目描述：** 一个完整的贷款管理系统，包含手机端用户界面、电脑端管理界面和后端API服务。

**主要功能：**
- **用户端：** 用户注册、登录、贷款申请、个人信息管理、身份验证、银行卡绑定
- **管理端：** 贷款申请审核、用户管理、产品管理、数据统计、系统设置
- **后端：** 提供RESTful API接口，支持用户端和管理端的业务需求

## 三层架构说明

本项目采用经典的三层架构设计模式，将系统分为表现层（Presentation Layer）、业务逻辑层（Business Logic Layer）和数据访问层（Data Access Layer）。各层职责清晰，便于维护和扩展。

### 架构图

```
┌─────────────────────────────────────────────────────────┐
│                   表现层 (Controller)                    │
│  Spring MVC | RESTful API | HTTP请求/响应处理           │
└────────────────────┬────────────────────────────────────┘
```

### 三层架构协作流程

#### 典型业务流程示例：用户注册

```
1. 表现层（UserController）
   └─ 接收POST请求：/api/users/register
   └─ 解析请求体：RegisterRequest
   └─ 参数验证：@Valid
   
2. 业务逻辑层（UserService）
   └─ 调用Repository检查手机号是否已存在
   └─ 创建User实体对象
   └─ 设置默认信用分
   └─ 调用Repository保存用户
   └─ 发送验证码（调用Redis）
   
3. 数据访问层（UserRepository）
   └─ 执行SQL：SELECT COUNT(*) FROM users WHERE phone_number = ?
   └─ 执行SQL：INSERT INTO users (...) VALUES (...)
   
4. 返回响应
   └─ Service返回业务结果
   └─ Controller构建HTTP响应
   └─ 返回JSON：{success: true, userId: "..."}
```

#### 数据流转

```
HTTP请求 (JSON)
    ↓
Controller (DTO对象)
    ↓
Service (Entity对象 ↔ DTO对象)
    ↓
Repository (Entity对象)
    ↓
数据库 (SQL)
    ↓
Repository (Entity对象)
    ↓
Service (DTO对象)
    ↓
Controller (JSON响应)
    ↓
HTTP响应 (JSON)
```

**4. 可维护性**

## 部署说明

### 后端部署

**环境要求：**
- JDK 21+
- Maven 3.6+
- MySQL 8.0+
- Redis（可选，用于缓存和会话存储）

**部署步骤：**

1. **配置数据库**
   ```sql
   CREATE DATABASE zongshe CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. **修改配置文件**
   - 编辑 `backend/src/main/resources/application.properties`
   - 修改数据库连接信息（URL、用户名、密码）
   - 配置JWT密钥（建议使用强随机字符串）
   - 根据需要调整其他配置参数

3. **编译打包**
   ```bash
   cd backend
   mvn clean package
   ```
   生成jar文件：`target/zongshe1-0.0.1-SNAPSHOT.jar`

4. **运行应用**
   ```bash
   java -jar target/zongshe1-0.0.1-SNAPSHOT.jar
   ```

5. **访问地址**
   - 管理端登录：`http://localhost:8080/admin-login.html`
   - API文档：`http://localhost:8080/swagger-ui.html`
   - API基础路径：`http://localhost:8080/api`

**生产环境建议：**
- 使用Nginx作为反向代理
- 配置HTTPS证书
- 使用systemd或supervisor管理进程
- 配置日志轮转
- 配置数据库连接池参数

### 前端部署

**管理端：**
- 已集成在后端Spring Boot项目中
- 访问：`http://localhost:8080/` 下的HTML文件
- 无需单独部署

**用户端（HTML文件）：**
- 直接部署到Web服务器（Nginx、Apache等）
- 或使用CDN托管静态文件
- 确保API地址配置正确（默认：`http://localhost:8080/api`）

**用户端（uni-app项目）：**

1. **构建H5版本**
   ```bash
   cd uni-preset-vue-vite
   npm install
   npm run build:h5
   ```
   输出到 `dist/build/h5/` 目录

2. **部署到Web服务器**
   - 将构建产物部署到Nginx、Apache等Web服务器
   - 或部署到CDN

3. **构建小程序版本**
   ```bash
   npm run build:mp-weixin  # 微信小程序
   ```
   输出到 `dist/build/mp-weixin/` 目录，使用微信开发者工具打开

4. **构建App版本**
   ```bash
   npm run build:app-plus  # App版本
   ```
   使用HBuilderX打开项目，进行云打包或本地打包

## 开发规范

### 代码规范
- Java代码遵循驼峰命名规范（camelCase）
- HTML/CSS/JS遵循语义化命名
- 统一使用UTF-8编码
- Java类名使用大驼峰（PascalCase）
- Java方法名和变量名使用小驼峰（camelCase）
- 常量使用大写下划线分隔（UPPER_SNAKE_CASE）

### API设计规范
- RESTful风格API设计
- 统一响应格式：`{success: boolean, data: object, message: string}`
- 使用HTTP状态码表示请求结果（200成功、400客户端错误、401未授权、500服务器错误等）
- URL使用小写字母和连字符（kebab-case）
- 使用复数名词表示资源集合（/api/users、/api/products）

### 数据库规范
- 表名使用下划线命名（snake_case）
- 字段名使用下划线命名（snake_case）
- 主键统一使用`id`
- 外键命名：`表名_id`（如`user_id`）
- 时间字段统一使用`created_at`、`updated_at`

### Git提交规范
- 提交信息使用中文，清晰描述修改内容
- 使用类型前缀：`feat:` 新功能、`fix:` 修复、`docs:` 文档、`style:` 格式、`refactor:` 重构、`test:` 测试、`chore:` 构建/工具
