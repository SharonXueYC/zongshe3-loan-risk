# 后端开发 - 预留接口扩展指南

## 文档说明

本文档说明如何为后续开发预留接口，特别是**风控规则**和**信誉分计算评估**功能的扩展方式。

**创建日期：** 2025-12-21  
**适用版本：** Spring Boot 3.2.5

---

## 一、架构设计概述

### 1.1 设计原则

采用**策略模式（Strategy Pattern）**和**依赖注入（Dependency Injection）**，为风控规则和信誉分计算预留可扩展的接口：

- **接口定义**：定义统一的接口规范
- **默认实现**：提供基础的默认实现，保证系统正常运行
- **扩展机制**：通过实现接口并注册为Spring Bean，系统自动发现并使用
- **优先级控制**：通过`@Order`注解或`getPriority()`方法控制执行顺序

### 1.2 预留接口列表

| 接口名称 | 用途 | 位置 |
|---------|------|------|
| `CreditScoreCalculator` | 信誉分计算策略接口 | `service/CreditScoreCalculator.java` |
| `RiskRuleEvaluator` | 风控规则评估器接口 | `service/RiskRuleEvaluator.java` |
| `RiskService` | 风控服务接口 | `service/RiskService.java` |

## 二、信誉分计算扩展

### 2.1 接口说明

**接口：** `CreditScoreCalculator`

**主要方法：**
- `calculateInitialCreditScore(User user)` - 计算用户初始信誉分
- `recalculateCreditScore(String userId)` - 重新计算用户信誉分
- `updateCreditScoreByLoanEvent(...)` - 根据贷款事件更新信誉分
- `getStrategyName()` - 获取策略名称
- `getPriority()` - 获取优先级

#### 步骤2：系统自动发现并使用

Spring会自动发现所有实现`CreditScoreCalculator`接口的Bean，`UserServiceImpl`会优先使用优先级最高的实现。

#### 步骤3：配置选择策略（可选）

如果需要通过配置指定使用哪个策略，可以添加配置类：

```java
@Configuration
public class CreditScoreConfig {
    
    @Bean
    @ConditionalOnProperty(name = "credit-score.strategy", havingValue = "advanced")
    public CreditScoreCalculator advancedCalculator() {
        return new AdvancedCreditScoreCalculator(...);
    }
    
    @Bean
    @ConditionalOnProperty(name = "credit-score.strategy", havingValue = "default", matchIfMissing = true)
    public CreditScoreCalculator defaultCalculator() {
        return new DefaultCreditScoreCalculator();
    }
}
```

### 2.3 使用示例

## 三、风控规则扩展

### 3.1 接口说明

**接口：** `RiskRuleEvaluator`

**主要方法：**
- `evaluateRisk(User user, LoanApplication application)` - 评估风险
- `getRuleName()` - 获取规则名称
- `getPriority()` - 获取优先级
- `isEnabled()` - 判断是否启用

### 3.2 扩展步骤

#### 步骤1：创建新的风控规则评估器

```java
package com.example.zongshe1.service.impl;

import com.example.zongshe1.entity.User;
import com.example.zongshe1.entity.LoanApplication;
import com.example.zongshe1.service.RiskRuleEvaluator;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

import java.util.HashMap;
import java.util.Map;

@Component
@Slf4j
@Order(2) // 设置优先级（在基础规则之后执行）
@RequiredArgsConstructor
public class AntiFraudRuleEvaluator implements RiskRuleEvaluator {

    private final BlacklistService blacklistService; // 假设的黑名单服务
    private final DeviceFingerprintService deviceService; // 假设的设备指纹服务

    @Override
    public Map<String, Object> evaluateRisk(User user, LoanApplication application) {
        Map<String, Object> result = new HashMap<>();
        
        // 1. 检查用户是否在黑名单中
        if (blacklistService.isUserBlacklisted(user.getUserId())) {
            result.put("riskScore", 100);
            result.put("riskLevel", 4);
            result.put("passed", false);
            result.put("reason", "用户已被列入黑名单");
            return result;
        }
        
        // 2. 检查设备指纹是否异常
        String deviceId = application.getDeviceId(); // 假设申请中有设备ID
        if (deviceService.isDeviceSuspicious(deviceId)) {
            result.put("riskScore", 85);
            result.put("riskLevel", 3);
            result.put("passed", false);
            result.put("reason", "设备指纹异常，疑似欺诈");
            return result;
        }
        
        // 3. 检查IP地址是否异常
        String ipAddress = application.getIpAddress(); // 假设申请中有IP地址
        if (blacklistService.isIpBlacklisted(ipAddress)) {
            result.put("riskScore", 90);
            result.put("riskLevel", 4);
            result.put("passed", false);
            result.put("reason", "IP地址已被列入黑名单");
            return result;
        }
        
        // 通过检查
        result.put("riskScore", 20);
        result.put("riskLevel", 1);
        result.put("passed", true);
        result.put("reason", "通过反欺诈检查");
        
        return result;
    }

    @Override
    public String getRuleName() {
        return "反欺诈规则（黑名单、设备指纹、IP检查）";
    }

    @Override
    public int getPriority() {
        return 2; // 在基础规则之后执行
    }

    @Override
    public boolean isEnabled() {
        // 可以通过配置控制是否启用
        return true;
    }
}
```

#### 步骤2：系统自动整合

`RiskServiceImpl`会自动发现所有实现`RiskRuleEvaluator`接口的Bean，按优先级顺序执行所有启用的评估器。

#### 步骤3：执行流程

1. 系统按优先级顺序调用所有启用的评估器
2. 如果任何一个评估器返回`passed=false`，整体评估失败
3. 综合所有评估器的结果，生成最终的风险评分和等级
4. 生成风控报告并保存到数据库

### 3.3 使用示例

```java
// 在贷款申请审核时自动调用
@Autowired
private RiskService riskService;

public void approveLoanApplication(Long applicationId) {
    // 执行风险评估
    Map<String, Object> riskResult = riskService.performRiskAssessment(applicationId);
    
    Boolean passed = (Boolean) riskResult.get("passed");
    if (!passed) {
        String reason = (String) riskResult.get("rejectReason");
        throw new BusinessException("风控检查未通过：" + reason);
    }
    
    // 继续审核流程...
}
```

## 五、最佳实践

### 5.1 优先级设置

- **基础规则**：优先级设置为1-10，最先执行
- **业务规则**：优先级设置为11-50
- **高级规则**：优先级设置为51-100
- **默认实现**：优先级设置为100+，作为兜底

### 5.2 异常处理

每个评估器应该独立处理异常，避免影响其他规则的执行：

```java
try {
    // 评估逻辑
} catch (Exception e) {
    log.error("风控规则评估异常", e);
    // 为了安全，异常时返回高风险
    result.put("passed", false);
    result.put("reason", "评估异常：" + e.getMessage());
}
```

### 5.3 性能考虑

- 对于耗时的评估（如调用外部API），考虑异步执行
- 使用缓存减少重复计算
- 批量评估时考虑并行处理

### 5.4 配置化

通过配置文件控制规则的启用/禁用：

```properties
# application.properties
risk-rule.anti-fraud.enabled=true
risk-rule.amount-check.enabled=true
risk-rule.realtime.enabled=false
```

## 七、总结

通过预留接口的方式，系统具备了良好的扩展性：

1. **无需修改现有代码**：新功能通过实现接口即可集成
2. **自动发现机制**：Spring自动发现并注入所有实现
3. **优先级控制**：通过优先级控制执行顺序
4. **灵活配置**：可以动态启用/禁用某个规则
5. **易于测试**：每个实现可以独立测试

**后续开发时，只需：**
1. 实现对应的接口
2. 添加`@Component`或`@Service`注解
3. 设置合适的优先级
4. 系统会自动使用新的实现
