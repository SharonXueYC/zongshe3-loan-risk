# 综设 II · 总体设计说明书

**项目名称：** 多数据源融合的互联网个人贷款风控系统 v1  
**版本：** 1.0  
**日期：** 2026-06

---

## 1. 设计目标

构建面向银行及贷款金融机构的在线个贷业务演示系统，实现：

- 借款端（Android APP）完整申贷与还款流程  
- 管理端（Web）审批、合同、放款与数据统计  
- **评分卡风控机制** + **多数据源融合**（库内 + 爬取外部特征）  
- 可模拟部署（Docker）与规范测试文档

## 3. 复杂工程问题分解

| 问题 | 模块 | 方案 |
|------|------|------|
| 多数据源融合 | `ExternalDataOrchestrator` + 适配器 | 并发拉取，统一 `FeatureSnapshot` |
| 数据爬取 | `DataCrawlerService` + Python 脚本 | Jsoup 解析演示 HTML，写入 `t_external_data_cache` |
| 模型/规则选择 | 评分卡 vs 规则链 | **选用评分卡为主模型**，规则链为补充（比选见 4.2） |
| 可扩展性 | `RiskRuleEvaluator` / `ExternalDataSourceAdapter` | 策略模式 + `@Order` 优先级 |

---

## 4. 方案比选

### 4.1 借款端技术选型

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 原生 Android | 性能最佳 | 开发周期长 | 不选 |
| **uni-app** | 一套代码出 Android/H5，课程演示快 | 依赖 DCloud 打包 | **选用** |
| HTML5 | 已实现 | 不符合任务书「安卓 APP」 | 作备用 |

### 4.2 风控流程方案比选

| 方案 | 描述 | 结论 |
|------|------|------|
| A. 仅规则引擎 | IF-ELSE 规则 | 简单但难体现「模型」 |
| **B. 评分卡 + 规则链** | 卡分阈值 + 外部数据规则 | **最优：符合任务书且可解释** |
| C. 机器学习模型 | XGBoost 等 | 样本与算力不足，v1 不采用 |

**选定流程：** 申请提交 → 爬取/读缓存 → 特征融合 → 评分卡计分 → 规则链汇总 → 写入 `risk_reports` → 管理端展示。

## 5. 子系统划分

| 子系统 | 职责 | 主要包/目录 |
|--------|------|-------------|
| 用户与认证 | 注册登录 JWT | `modules/user`, `modules/auth` |
| 贷款业务 | 申请/审批/合同/放款 | `modules/loanapplication`, `service/Contract*` |
| 还款 | 计划生成/还款/逾期 | `modules/repay` |
| **风控** | 评分卡、规则、报告 | `modules/risk` |
| **数据爬取** | 爬取、缓存、定时刷新 | `modules/crawler`, `crawler/` |
| 管理统计 | 控制台/报表 | `modules/statistics` |
| 借款端 | Android 五页 | `apps/uni-client/src/pages` |
| 管理端 | Vue Dashboard | `frontend/` |

## 6. 部署架构

Docker Compose：MySQL + Redis + Backend + Nginx（用户 H5 / 管理端 / API 同源）。详见 `deploy/README.md`。
