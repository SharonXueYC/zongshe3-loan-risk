## 一、用户端用例

### UC-01：用户注册

**用例描述：** 新用户通过手机号、身份证号等信息注册账号

**具体功能：**
- 用户填写注册信息（手机号、身份证号、用户名等）
- 系统验证信息唯一性
- 创建用户账号并设置默认信用分
- 发送短信验证码

**前置条件：** 无（未登录状态）

**基本流程：**
1. 用户访问注册页面
2. 填写注册表单（手机号、身份证号、用户名、密码等）
3. 前端校验表单格式
4. 提交注册请求
5. 后端验证信息唯一性
6. 创建用户记录
7. 发送验证码
8. 返回注册结果

#### 前端操作
- **页面：** `register-prototype.html`
- **操作步骤：**
  1. 显示注册表单（手机号、身份证号、用户名、密码输入框）
  2. 实现表单验证（手机号格式、身份证号格式、密码强度等）
  3. 监听表单提交事件
  4. 调用API：`POST /api/users/register`
  5. 传递请求参数：`{phoneNumber, idCardNumber, userName, password}`
  6. 处理响应：
     - 成功：显示"注册成功"提示，跳转到验证码输入页面
     - 失败：显示错误信息（如"手机号已注册"）
  7. 实现倒计时功能（60秒内不能重复发送）

#### 后端操作
- **后端核心工作：** 验证用户信息唯一性，创建用户记录并设置默认信用分，发送验证码存储到Redis
- **Controller：** `UserController.register()`
- **Service：** `UserService.register()`
- **Repository：** `UserRepository`
- **操作步骤：**
  1. 接收注册请求，使用`@Valid`验证请求参数
  2. 调用`UserRepository.existsByPhoneNumber()`检查手机号是否存在
  3. 调用`UserRepository.existsByIdCardNumber()`检查身份证号是否存在
  4. 如果已存在，返回错误信息
  5. 创建User实体对象：
     - 生成UUID作为userId
     - 设置用户基本信息
     - 设置默认信用分（从配置读取，默认500分）
     - 设置用户状态为正常（status=1）
  6. 使用BCrypt加密密码（如果实体有密码字段）
  7. 调用`UserRepository.save()`保存用户
  8. 调用`sendVerificationCode()`发送短信验证码（存储到Redis，5分钟过期）
  9. 返回注册结果：`{success: true, userId: "xxx", message: "注册成功"}`

### UC-02：用户登录（密码登录）

**用例描述：** 已注册用户通过手机号和密码登录系统

**具体功能：**
- 用户输入手机号和密码
- 系统验证用户身份
- 生成JWT令牌
- 返回用户信息和令牌

**前置条件：** 用户已完成注册

**基本流程：**
1. 用户访问登录页面
2. 输入手机号和密码
3. 前端校验格式
4. 提交登录请求
5. 后端验证用户身份
6. 生成JWT令牌
7. 返回登录结果和令牌

#### 前端操作
- **页面：** `login-prototype.html`
- **操作步骤：**
  1. 显示登录表单（手机号、密码输入框）
  2. 实现表单验证
  3. 监听表单提交事件
  4. 调用API：`POST /api/users/login`
  5. 传递请求参数：`{phoneNumber, password}`
  6. 处理响应：
     - 成功：保存token到localStorage，保存用户信息，跳转到首页
     - 失败：显示错误信息（如"用户不存在"、"密码错误"、"账户已冻结"）
  7. 实现"记住我"功能（保存用户名到localStorage）

#### 后端操作
- **后端核心工作：** 验证用户身份和密码，检查账户状态，生成JWT令牌返回给前端
- **Controller：** `UserController.login()`
- **Service：** `UserService.login()`
- **Repository：** `UserRepository`
- **操作步骤：**
  1. 接收登录请求，验证请求参数
  2. 调用`UserRepository.findByPhoneNumber()`查询用户
  3. 如果用户不存在，返回错误信息
  4. 检查用户状态（如果status=2，账户已冻结，返回错误）
  5. 使用BCrypt验证密码（比较输入的密码和存储的加密密码）
  6. 如果密码错误，返回错误信息
  7. 调用`JwtUtil.generateToken()`生成JWT令牌（包含userId和phoneNumber，有效期2小时）
  8. 将User实体转换为UserDTO
  9. 返回登录结果：`{success: true, token: "xxx", expiresIn: 7200, userInfo: {...}}`

### UC-03：验证码登录

**用例描述：** 用户通过手机号和短信验证码登录，如果用户不存在则自动注册

**具体功能：**
- 用户输入手机号
- 获取短信验证码
- 输入验证码登录
- 自动注册新用户（如果不存在）

**前置条件：** 无（未登录状态）

**基本流程：**
1. 用户访问登录页面，选择"验证码登录"
2. 输入手机号
3. 点击"获取验证码"按钮
4. 系统发送验证码到手机
5. 用户输入验证码
6. 提交登录请求
7. 系统验证验证码
8. 如果用户不存在，自动注册
9. 生成JWT令牌并返回

#### 前端操作
- **页面：** `login-prototype.html`
- **操作步骤：**
  1. 提供"验证码登录"选项
  2. 显示手机号和验证码输入框
  3. 实现"获取验证码"按钮：
     - 验证手机号格式
     - 调用API：`POST /api/users/send-otp`
     - 传递参数：`{phoneNumber}`
     - 成功后显示倒计时（60秒）
  4. 用户输入验证码后，调用API：`POST /api/users/login-otp`
  5. 传递参数：`{phoneNumber, verificationCode}`
  6. 处理响应：
     - 成功：保存token和用户信息，跳转首页
     - 失败：显示错误信息（如"验证码错误"、"验证码已过期"）

#### 后端操作
- **后端核心工作：** 生成验证码存储到Redis，验证码登录时校验验证码有效性，用户不存在则自动注册
- **Controller：** `UserController.sendOtp()`, `UserController.loginWithOtp()`
- **Service：** `UserService.sendVerificationCode()`, `UserService.loginWithOtp()`
- **Repository：** `UserRepository`
- **Redis：** 验证码存储
- **操作步骤（发送验证码）：**
  1. 接收发送验证码请求
  2. 验证手机号格式
  3. 生成6位随机数字验证码
  4. 存储到Redis：`key: "otp:" + phoneNumber, value: code, expire: 5分钟`
  5. 调用短信服务发送验证码（模拟实现：记录日志）
  6. 返回结果：`{success: true, message: "验证码已发送"}`
- **操作步骤（验证码登录）：**
  1. 接收验证码登录请求
  2. 从Redis获取验证码：`key: "otp:" + phoneNumber`
  3. 如果验证码不存在或已过期，返回错误
  4. 比较输入的验证码和Redis中的验证码
  5. 如果验证码错误，返回错误
  6. 验证成功后，删除Redis中的验证码
  7. 调用`UserRepository.findByPhoneNumber()`查询用户
  8. 如果用户不存在：
     - 自动创建用户（设置默认信用分、生成userId）
     - 保存到数据库
  9. 生成JWT令牌
  10. 返回登录结果

### UC-04：获取用户信息

**用例描述：** 用户查看自己的个人信息

**具体功能：**
- 显示用户基本信息（姓名、手机号、身份证号、信用分等）
- 显示用户状态（正常/冻结）

**前置条件：** 用户已登录（有有效的JWT令牌）

**基本流程：**
1. 用户访问个人信息页面
2. 前端从localStorage获取userId或从token解析userId
3. 调用获取用户信息API
4. 后端验证token有效性
5. 查询用户信息
6. 返回用户信息（敏感信息脱敏处理）

#### 前端操作
- **页面：** `profile/profile-complete.html` 或个人信息页面
- **操作步骤：**
  1. 页面加载时，从localStorage获取userId或解析token获取userId
  2. 调用API：`GET /api/users/{userId}`
  3. 在请求头中添加Authorization：`Bearer {token}`
  4. 处理响应：
     - 成功：展示用户信息（姓名、手机号、身份证号脱敏显示、信用分、状态等）
     - 失败：显示错误信息或跳转到登录页

#### 后端操作
- **后端核心工作：** 根据用户ID查询用户信息，对敏感数据进行脱敏处理后返回给前端
- **Controller：** `UserController.getUserInfo()`
- **Service：** `UserService.getUserInfo()`
- **Repository：** `UserRepository`
- **操作步骤：**
  1. 接收请求，从路径参数获取userId
  2. 可选：从请求头获取token，验证token有效性（如果需要）
  3. 调用`UserRepository.findByUserId()`查询用户
  4. 如果用户不存在，抛出异常或返回错误
  5. 将User实体转换为UserDTO（脱敏处理：身份证号、手机号中间位数用*替代）
  6. 返回用户信息：`{userId, userName, phoneNumber: "138****1234", idCardNumber: "110***********5678", creditScore, userStatus, ...}`

**用例描述：** 用户修改自己的个人信息（如用户名、手机号等）

**具体功能：**
- 用户修改可更改的个人信息
- 系统验证新信息的有效性
- 更新数据库中的用户信息

**前置条件：** 用户已登录

**基本流程：**
1. 用户进入个人信息编辑页面
2. 修改信息字段
3. 前端验证格式
4. 提交更新请求
5. 后端验证数据
6. 更新数据库
7. 返回更新结果

#### 前端操作
- **页面：** 个人信息编辑页面
- **操作步骤：**
  1. 显示可编辑的用户信息表单
  2. 预填充当前用户信息
  3. 用户修改信息后，点击"保存"按钮
  4. 前端验证格式（如手机号格式）
  5. 调用API：`PUT /api/users/{userId}?userName=xxx&phoneNumber=xxx`
  6. 在请求头中添加Authorization：`Bearer {token}`

     - 成功：显示"更新成功"提示，刷新用户信息显示

- **Service：** `UserService.updateUserInfo()`
- **Repository：** `UserRepository`

  2. 验证token（从请求头获取）
  3. 调用`UserRepository.findByUserId()`查询用户
  4. 如果用户不存在，返回错误
  5. 如果更新手机号，检查新手机号是否已被其他用户使用
  6. 更新用户实体字段
  7. 调用`UserRepository.save()`保存更新
  8. 返回更新结果：`{success: true, message: "用户信息更新成功"}`

### UC-06：检查贷款资格

**用例描述：** 用户查看自己是否符合贷款条件

**具体功能：**
- 根据用户的信用分判断是否符合贷款条件
- 显示资格检查结果

**前置条件：** 用户已登录

**基本流程：**
1. 用户访问贷款资格检查页面或点击"检查资格"按钮
2. 前端调用检查资格API
3. 后端查询用户信用分
4. 判断是否达到最低信用分要求
5. 返回检查结果

#### 前端操作
- **页面：** 贷款首页或个人信息页面
- **操作步骤：**
  1. 显示"检查贷款资格"按钮或页面加载时自动检查
  2. 调用API：`GET /api/users/{userId}/loan-qualification`
  3. 传递Authorization token
  4. 处理响应：
     - 符合条件：显示"符合贷款条件"提示，可以继续申请
     - 不符合：显示"不符合贷款条件"提示，说明原因（如"信用分不足450分"）

#### 后端操作
- **后端核心工作：** 查询用户信用分，与系统配置的最低信用分阈值进行比较，返回是否符合贷款条件
- **Controller：** `UserController.checkLoanQualification()`
- **Service：** `UserService.checkLoanQualification()`
- **Repository：** `UserRepository`
- **操作步骤：**
  1. 接收请求，获取userId
  2. 调用`UserRepository.findByUserId()`查询用户
  3. 获取用户信用分（creditScore）
  4. 从配置读取最低信用分要求（minCreditScoreForLoan，默认450）
  5. 比较：`creditScore >= minCreditScoreForLoan`
  6. 返回结果：`{success: true, qualified: true/false, message: "符合/不符合贷款条件"}`

### UC-08：提交贷款申请

**用例描述：** 用户提交贷款申请

**具体功能：**
- 用户选择贷款产品
- 填写申请信息（金额、期限、用途等）
- 提交申请
- 系统创建申请记录

**前置条件：** 用户已登录且符合贷款资格

**基本流程：**
1. 用户访问贷款申请页面
2. 选择贷款产品
3. 填写申请信息（金额、期限、还款方式、用途说明等）
4. 前端验证信息（金额是否在范围内、期限是否有效等）
5. 提交申请
6. 后端验证用户资格和申请信息
7. 创建申请记录
8. 返回申请结果

#### 前端操作
- **页面：** `loan-home.html`
- **操作步骤：**
  1. 显示贷款产品列表（从产品列表API获取）
  2. 用户选择产品后，显示该产品的详细信息（利率、额度范围、期限范围等）
  3. 显示申请表单：
     - 贷款金额输入框（带范围提示）
     - 贷款期限选择器（月）
     - 还款方式选择（等额本息/等额本金等）
     - 用途说明文本域
  4. 前端验证：
     - 金额在产品范围内
     - 期限在产品允许范围内
     - 必填项已填写
  5. 用户点击"提交申请"按钮
  6. 调用API：`POST /api/loan-applications/submit`
  7. 在请求头中添加Authorization：`Bearer {token}`
  8. 传递请求体：`{loanAmount, loanTerm, loanType, repaymentMode, interestRate, description}`
  9. 处理响应：
     - 成功：显示"申请提交成功"提示，跳转到申请成功页面（`loan-submitted.html`）
     - 失败：显示错误信息（如"不符合贷款条件"、"金额超出范围"）

#### 后端操作
- **后端核心工作：** 验证用户贷款资格和申请信息有效性，创建贷款申请记录并生成申请单号，保存到数据库
- **Controller：** `LoanApplicationController.submitApplication()`
- **Service：** `LoanApplicationService.submitApplication()`
- **Repository：** `LoanApplicationRepository`, `UserRepository`, `ProductRepository`
- **操作步骤：**
  1. 接收申请请求，从请求头解析token获取userId
  2. 验证token有效性
  3. 调用`UserRepository.findByUserId()`查询用户
  4. 检查用户状态（是否冻结）
  5. 调用`UserService.checkLoanQualification()`检查贷款资格
  6. 验证申请金额是否在系统配置范围内（min-loan-amount, max-loan-amount）
  7. 如果指定了产品，调用`ProductRepository.findById()`查询产品，验证金额和期限是否符合产品要求
  8. 创建LoanApplication实体：
     - 生成申请单号（如：LA-20231221-001）
     - 设置申请人信息（从User关联）
     - 设置申请金额、期限、类型等
     - 设置状态为pending（待审核）
     - 设置申请时间
  9. 调用`LoanApplicationRepository.save()`保存申请
  10. 返回结果：`{success: true, applicationId: 123, applicationNo: "LA-xxx", message: "申请提交成功"}`

## 四、技术实现要点

### 前端技术要点
1. **API调用统一封装**：使用Axios或Fetch API，统一处理请求和响应
2. **Token管理**：登录后保存token到localStorage，所有API请求携带token
3. **错误处理**：统一处理API错误，显示友好的错误提示
4. **表单验证**：前端和后端双重验证
5. **数据脱敏**：敏感信息（身份证号、手机号）显示时进行脱敏
6. **图表绘制**：使用Canvas API绘制统计图表

### 后端技术要点
1. **JWT认证**：所有需要登录的接口验证JWT token
2. **权限控制**：管理员接口验证权限（如superAdmin、admin等角色）

6. **日志记录**：记录关键操作的日志
