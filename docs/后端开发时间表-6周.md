# 综合贷款管理系统 - 后端开发时间表（6周）

## 文档说明
本文档为综合贷款管理系统后端开发制定详细的6周开发时间表，不包含数据库设计和测试工作。

**总时长：** 6周（30个工作日）  
**开发模式：** 敏捷开发，每周迭代  
**技术栈：** Spring Boot 3.2.5 + Java 21 + Spring Data JPA + Spring Security + JWT

---

## 时间表概览

| 周次 | 时间范围 | 主要任务 | 交付物 |
|------|---------|---------|--------|
| 第1周 | 第1-5天 | 项目搭建、基础架构、认证授权 | 项目框架、JWT认证 |
| 第2周 | 第6-10天 | 用户管理、产品管理 | 用户CRUD、产品CRUD |
| 第3周 | 第11-15天 | 贷款申请、审核流程 | 申请提交、审核功能 |
| 第4周 | 第16-20天 | 合同管理、放款管理 | 合同生成、放款功能 |
| 第5周 | 第21-25天 | 还款计划、数据统计 | 还款计划、统计接口 |
| 第6周 | 第26-30天 | 系统配置、优化完善 | 配置管理、代码优化 |

## 第一周：项目搭建与基础架构

### 本周任务清单

#### 1. 项目初始化与环境搭建
- 创建Spring Boot项目，配置Maven依赖
- 配置`application.properties`（数据库连接、JWT配置等）
- 创建项目目录结构（Controller、Service、Repository、Entity、DTO等）
- 配置开发环境（IDE、JDK 21、Maven）
- 创建主启动类`Zongshe1Application`

#### 2. 基础配置与工具类
- 创建`CorsConfig`配置类，解决跨域问题
- 创建`SecurityConfig`配置类，配置Spring Security
- 创建`WebConfig`配置类，配置静态资源
- 创建`ApplicationProperties`配置类，绑定配置属性
- 创建`JwtUtil`工具类，实现JWT生成和验证
- 创建`EncryptionUtil`工具类，实现密码加密（BCrypt）

#### 3. 全局异常处理与参数验证
- 创建`GlobalExceptionHandler`全局异常处理器
- 创建`BusinessException`自定义业务异常类
- 配置统一响应格式（成功/失败响应）
- 实现参数验证异常处理，返回详细错误信息
- 创建基础DTO类（请求/响应DTO基类）

#### 4. 实体类与Repository层
- 创建核心实体类：`User`、`Admin`、`Product`、`LoanApplication`
- 配置实体关系映射（@OneToMany、@ManyToOne等）
- 创建Repository接口：`UserRepository`、`AdminRepository`、`ProductRepository`、`LoanApplicationRepository`
- 实现基础查询方法（findBy、existsBy等）
- 配置JPA审计（创建时间、更新时间）

#### 5. 用户认证与授权（用户端）
- 创建`UserController`，实现用户注册接口
- 创建`UserService`和`UserServiceImpl`，实现注册业务逻辑
- 实现用户密码登录接口
- 实现验证码发送接口（模拟短信服务）
- 实现验证码登录接口
- 实现JWT令牌生成和返回
- 配置用户注册和登录的事务管理

## 第三周：贷款申请与审核

### 本周任务清单

#### 1. 贷款申请提交
- 创建`LoanApplicationController`，实现贷款申请提交接口
- 创建`LoanApplicationService`和`LoanApplicationServiceImpl`
- 实现申请提交业务逻辑：
  - 验证用户贷款资格（信用分检查）
  - 验证申请金额和期限范围
  - 验证产品信息（如果指定产品）
  - 生成唯一申请单号
  - 创建申请记录
- 创建`LoanApplicationDTO`和`LoanApplicationRequest`
- 配置申请提交的事务管理

#### 2. 贷款申请查询
- 实现用户申请列表查询接口（GET /api/loan-applications，用户只能查看自己的）
- 实现管理员申请列表查询接口（支持分页、筛选）
- 实现申请详情查询接口（GET /api/loan-applications/{id}）
- 实现申请列表筛选功能（状态、类型、关键词搜索）
- 实现申请状态流转验证逻辑

#### 3. 贷款申请审核功能
- 实现申请审核通过接口（PUT /api/loan-applications/{id}/approve）
- 实现申请审核拒绝接口（PUT /api/loan-applications/{id}/reject）
- 实现审核状态验证（只能审核pending状态的申请）
- 实现审核信息记录（审核人、审核时间、审核备注）
- 配置审核操作的事务管理
- 实现审核后的业务触发（可选：生成合同触发点）

#### 4. 合同实体与Repository
- 创建合同相关实体类：`Contract`、`RepayPlan`、`DisburseRecord`
- 配置实体关系映射（Contract与LoanApplication、RepayPlan等）
- 创建Repository接口：`ContractRepository`、`RepayPlanRepository`、`DisburseRecordRepository`
- 实现合同相关查询方法
- 设计合同状态流转规则

#### 5. 电子合同生成
- 创建`ContractService`和`ContractServiceImpl`
- 实现电子合同生成功能：
  - 验证申请状态（必须为approved）
  - 生成唯一合同编号
  - 构建合同内容（基于申请信息和产品信息）
  - 创建合同记录
- 创建`ContractDTO`
- 实现合同生成接口（POST /api/contracts/generate）
- 配置合同生成的事务管理

## 第四周：合同管理与放款管理

### 本周任务清单

#### 1. 合同签署与状态同步
- 创建`ContractController`
- 实现合同签署接口（PUT /api/contracts/{id}/sign）
- 实现签署权限验证（用户只能签署自己的合同）
- 实现合同状态更新（用户签署、管理员签署、双方已签署）
- 实现状态同步逻辑（双方签署后触发后续流程）
- 实现合同状态查询接口（GET /api/contracts/{id}/status）

#### 2. 还款计划生成
- 实现还款计划生成功能：
  - 根据贷款金额、期限、利率、还款方式计算每期还款金额
  - 支持等额本息、等额本金、先息后本、一次性还本付息
  - 计算每期还款日期
  - 创建还款计划记录
- 实现还款计划生成接口（POST /api/repay-plans/generate）
- 实现还款计划查询接口（GET /api/repay-plans?contractId=xxx）
- 创建`RepayPlanDTO`

#### 3. 放款执行功能
- 创建`DisburseRecordController`
- 实现放款执行接口（POST /api/disburse-records）
- 实现放款条件验证：
  - 验证合同签署状态（必须双方已签署）
  - 验证申请状态
  - 验证放款金额
- 实现放款记录创建
- 实现申请状态更新（更新为disbursed）
- 配置放款操作的事务管理
- 创建`DisburseRecordDTO`

#### 4. 定时任务与逾期处理
- 在主启动类添加`@EnableScheduling`注解
- 创建`ScheduledTasks`定时任务类
- 实现逾期检测定时任务（每天执行）：
  - 查询所有逾期的还款计划
  - 计算逾期天数和罚息
  - 更新还款计划状态
- 实现逾期提醒功能（异步发送通知）
- 配置定时任务执行时间（如每天凌晨2点）

#### 5. 还款计划管理完善
- 实现还款计划状态更新接口
- 实现还款记录接口（模拟还款操作）
- 完善还款计划查询功能（支持状态筛选）
- 实现还款计划统计功能（已还、未还、逾期统计）
- 优化还款计划生成逻辑（处理边界情况）

## 风险提示与应对措施

### 风险1：技术难点学习时间不足
**应对措施：**
- 提前学习JWT、Spring Security等关键技术
- 遇到问题及时查阅文档和寻求帮助
- 预留缓冲时间处理技术难点

### 风险2：业务逻辑理解偏差
**应对措施：**
- 开发前仔细阅读业务需求文档
- 与产品经理或业务人员及时沟通
- 关键业务逻辑实现后进行评审

### 风险3：进度延期
**应对措施：**
- 每周进行进度检查
- 及时调整任务优先级
- 非核心功能可以适当简化

### 风险4：代码质量问题
**应对措施：**
- 遵循编码规范
- 及时进行代码审查
- 第6周专门进行代码优化

## 开发建议

1. **每日站会**：每天开始前，回顾前一天进度，规划当天任务
2. **及时提交**：完成一个功能模块后及时提交代码，避免代码丢失
3. **文档同步**：代码和文档同步更新，保持一致性
4. **及时测试**：每完成一个接口，及时进行接口测试
5. **问题记录**：遇到问题及时记录，便于后续总结
6. **代码审查**：关键功能完成后进行代码审查
7. **进度跟踪**：每周总结进度，及时调整计划
