## 3.2 用户端前端

通过本阶段的开发，我负责的用户端前端模块已经基本完成了移动端贷款全流程的页面搭建、交互逻辑、接口联调和功能测试工作。用户端前端作为个人贷款风控系统面向普通用户的重要入口，主要帮助用户完成从注册登录、贷款申请、额度查询到还款管理的完整操作流程。目前该模块已经能够支持系统的基本演示和核心业务流程运行。

在页面搭建方面，用户端前端已经完成了登录页面、注册页面、首页（main-home.html）、借款申请页面、额度查询页面、还款管理页面、银行卡管理页面、借款记录页面、人脸验证页面、额度评估进度页面和借款提交成功页面等主要功能页面。整体采用 HTML 多页应用（MPA）结构，首页以可借额度卡片、功能菜单网格和快捷操作列表组织入口，用户登录后通过网格菜单或页面跳转进入借款、还款、额度查询、银行卡、个人资料等功能模块。**（原稿「底部 Tab 导航（首页、借款、还款、我的）」与云上演示 H5 不符，已按 main-home.html 实际布局修正；仓库中 uni-app 源码含 Tab 配置，但答辩演示以 HTML H5 为准。）** 这样的页面结构便于 Nginx 静态托管与手机浏览器访问，功能分类也比较清晰。

在登录注册方面，登录页已支持密码登录和验证码登录两种方式，密码登录包含账号输入、密码显示/隐藏、记住我功能（界面开关已实现，**目前 Token 仍同时写入 localStorage 与 sessionStorage，后续可与「记住我」策略进一步联动**）；验证码登录包含手机号输入和60秒倒计时。注册页采用两步注册模式，先验证手机号再设置密码，可提前拦截无效手机号，提升注册成功率。注册成功后自动跳转隐私协议授权页，满足合规要求。登录成功后Token存入localStorage实现登录态持久化，未登录用户访问需鉴权页面时自动跳转登录页；访问 `/?logout=1` 可清除本地登录态，便于演示机切换账号。

在贷款申请方面，借款申请页面已完成金额输入（含快捷金额选择——十分之一、一半、全部可借）、期限选择（6/12/24期）、还款方式选择（等额本息/等额本金）以及实时还款计算器等功能。用户调整任意参数时，计算器立即更新月供、总利息和总还款金额，让用户在提交申请前充分了解借款成本。实时计算器采用等额本息和等额本金两种计算逻辑，通过JavaScript在用户输入时即时触发计算并更新页面展示。提交申请时调用贷款申请接口，成功后**跳转借款记录页（loan-records.html?submitted=1）查看申请与进度**（**原稿「跳转借款提交成功页」；loan-submitted.html 仍保留作展示备用**），整个流程顺畅，交互反馈及时。

在额度查询方面，额度查询页面已完成信誉分环形进度条展示、可借额度展示、信誉等级展示和信誉分构成明细列表等功能。环形进度条使用SVG配合stroke-dasharray和stroke-dashoffset实现，**通过 CSS transition 驱动 stroke-dashoffset 平滑过渡**（**原稿 requestAnimationFrame，与 credit-limit.html 实现不符**）。页面同时展示各加减分因子的名称、描述和分值，让用户清楚了解信誉分的构成。页面底部提供"提交增信资料"功能，用户可通过多选方式选择学历证明、收入证明、房产证明、社保缴纳证明等资料类型并上传附件，提交后系统重新计算额度并刷新页面，实现了用户主动提额的闭环。

在还款管理方面，还款页面已完成"待还计划"和"还款记录"**两个功能区块**（**原稿「两大 Tab」；实际为同页上下卡片布局，非 Tab 切换**）。待还计划列表展示每期还款计划的编号、期数、到期日、状态和剩余应还金额，每条计划支持全额还款和部分还款两种操作；部分还款时前端校验金额不超过剩余应还金额，减少无效请求。还款操作跳转付款确认页进行二次确认，清晰展示还款金额和计划信息，用户确认后才提交支付请求，有效降低资金误操作风险。还款记录列表支持按借款申请日期范围、还款日期范围、金额范围进行筛选，筛选逻辑通过数组filter方法在前端实现，满足用户账目管理需求。

在银行卡管理和借款记录方面，银行卡管理页面已完成银行卡列表展示和绑定新卡功能，绑卡表单包含开户行、银行卡号、预留手机号、短信验证码四个字段，验证码支持60秒倒计时，绑定成功后数据存入localStorage按用户ID隔离缓存。借款记录页面已完成历史申请列表展示，每条记录展示申请编号、状态标签（审核中/已通过/已拒绝/已放款等，**优先使用后端 statusText**）、借款金额、申请时间、风控结果，并以进度条展示审核进度（已提交→风控评估→人工审核→结果），让用户对申请状态一目了然，减少了因信息不透明而产生的焦虑。

在人脸验证和额度计算方面，人脸验证页面已完成圆形取景框设计和三步验证流程（眨眼→点头→保持不动），**为 H5 演示模拟流程，未调用真实摄像头 SDK**；验证通过后跳转**额度评估进度页（review-progress.html）**。**额度评估进度页**展示审核进度步骤，基于真实后端接口串行调用信用分评估和风控评估接口，每步完成后自动进入下一步，非模拟定时器，让用户了解额度计算全过程，增强了系统的透明度和可信度。

在网络请求封装方面，**已在 js/user-session.js 中封装 apiRequest 等公共方法**，基于fetch API配置基地址，请求头自动携带Token；各业务页面亦按需封装本地 request 函数。**401 等异常主要依靠 ensureSessionOrRedirect 与各页错误提示处理；目前尚未实现带 AbortController 的全局 10 秒超时封装**（**原稿「统一 request + 10 秒超时」与代码不符**）。**Toast 提示为各页面内置 showToast 实现**；Loading 态多采用按钮禁用与「提交中…」文案，**尚未抽离为统一的 Modal/Loading 组件**（**原稿「通用 Toast/Modal/Loading 多页复用」部分夸大**）。

从完成度来看，用户端前端目前整体完成度约为85%。其中，登录注册、**首页**、借款申请、借款记录等核心功能模块完成度较高（约90%）；额度查询、还款管理、银行卡管理、额度评估进度等功能模块已完成基础功能，在细节上还有优化空间（约80%-85%）；人脸验证模块受限于真实摄像头调用需要原生环境支持，目前完成了模拟验证流程（约80%）。页面基础结构和主要功能模块已基本完成，能够支撑系统完整演示流程。

目前用户端前端仍然存在一些不足。第一，部分页面的交互细节还不够完善，例如加载提示、空数据提示、错误提示等还可以进一步优化，弱网环境下的加载体验有待提升。第二，MPA架构下多页面数据同步虽然已有localStorage+URL参数的方案，但在某些边界场景下仍存在数据不一致的可能，需要继续完善。第三，移动端适配在主流机型上表现良好，但在部分小屏设备（宽度<360px）上还存在元素重叠或布局错位的问题，需要继续优化。第四，页面测试目前主要集中在正向流程，边界场景和异常场景的测试覆盖还不够充分，如弱网中断、接口超时、数据异常等情况。第五，部分页面首屏加载速度还有优化空间，图片资源未做压缩处理，列表渲染性能有待提升。

针对以上不足，后续我计划从以下几个方面进行改进：首先，继续完善各页面的交互反馈，在数据加载、操作成功、操作失败和空数据场景下提供更加明确的提示，增加骨架屏占位提升弱网环境下的加载体验。其次，完善MPA架构下的数据同步机制，通过pageshow事件监听BFCache恢复场景，增加刷新标记的清理逻辑，确保数据一致性。再次，针对小屏设备（宽度<360px）进行专项适配，使用clamp()函数弹性字体、媒体查询调整布局、flex-wrap处理换行，并在多台真实设备上进行验证。然后，补充边界场景和异常场景的测试用例，使用Chrome DevTools模拟Slow 3G网络测试弱网环境，覆盖表单为空提交、网络异常、重复点击、数据为空等情况。最后，对图片资源进行压缩处理，使用懒加载优化首屏速度，优化列表渲染减少卡顿；**并逐步统一 request 封装（含超时与 401 处理）、抽取公共 Toast/Loading，使「记住我」与 Token 存储策略真正联动**。

总体来看，本阶段用户端前端已经完成了个人贷款风控系统移动端的主要功能，能够支持用户完成注册登录、贷款申请、额度查询、还款管理和银行卡绑定等核心操作。虽然仍然存在一些细节需要继续完善，但整体功能框架已经基本形成，为用户提供了一条从入门到完成贷款申请再到还款管理的完整闭环体验，为后续系统优化和最终展示奠定了基础。
