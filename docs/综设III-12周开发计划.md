# 综设 III · 组员开发计划

**项目：** 多数据源融合的互联网个人贷款风控系统 v2  
**基线：** 综设 II 已能跑（登录、产品、申贷、评分卡、合同、放款、还款、Web、uni-app）。III **不要重写这些**，只改入口、接新契约、加扩展。  
**更新日期：** 2026-09-12  
**怎么用本文：** 先看第 1 节「要达成什么」，再看第 4 节自己那一周。目录冲突看 `docs/综设III-代码分工边界.md`。风控公式看 `docs/综设III-多模型风控设计.md`。给老师看的简表是 `docs/综设III-周计划-指导教师.md`。

**节奏：** 周一同步接口增量 → 周四自测 → 周五全员联调。第 1～10 周只修阻断缺陷；第 11～12 周集中测试，不再开新功能。

## 0. 全组必须先对齐的口径

**3 个 Spring Boot（老师说的「两个」指两个业务服务）：**

| 进程 | 端口 | 里面是谁 | 不要做什么 |
|------|------|----------|------------|
| `gateway/` | 8088 | 薛雨宸 | 不要删、不要并进 backend |
| `backend/` 主业务 | 8080 | 熊梓伊（信贷包）+ 薛雨宸（`modules/ops/`） | 不要再拆 `loan-service` / `platform-service` |
| 风控（后拆） | 8081 | 岳炜杰 | 第 2 周不要为拆而拆；四模型能演示后再迁 |

前端（APP / Web）**只打** `http://localhost:8088`，不要直连 8080/8081。  
库：第 9 周起 `loan_db`（信贷+平台表）+ `risk_db`（报告/快照），同一 MySQL。  
Git：各人走自己的 `feature-*` 分支再 PR，不要直推 `main`。

```
APP / Web → 网关 8088
              ├─ /api/users、/api/admin、/api/products、/api/loan-applications、
              │  /api/contracts、/api/repayment、/api/ops … → 主业务 8080
              └─ /api/risk、/api/credit、/api/admin/crawler
                    → 现在仍 8080；拆出后改环境变量 RISK_SERVICE_URI=http://127.0.0.1:8081
主业务 8080 ──HTTP──► 风控 assess / replay / reevaluate
```

## 8. 附录

### 8.1 技术栈（采用 / 不采用）

采用：Gateway、Caffeine+Redis、RabbitMQ 延迟队列、两 schema、**A/B/C/F 四卡**、真爬公示、AI 客服 HTTP。  
不采用：Kafka、ShardingSphere、训练机器学习、Drools、独立 platform-service。  
禁止：爬个人征信/运营商、破解验证码、打全国执行库。

### 8.2 风控建议新写的类（岳）

`ApplicationScoreCard`（A）、`FraudScoreCard`（F）、`BehaviorScoreCard`（B）、`CollectionScoreCard`（C）、`TwoStageRiskOrchestrator`、快照读写。

### 8.3 借款端 APK

HBuilderX：`apps/uni-client` → 发行 → 原生 App-云打包 → Android。应用名「闪借」。真机不要用 `10.0.2.2`，登录页必须能填网关。步骤见 `apps/uni-client/README-Android打包.md`。

### 8.4 本机启动顺序

1. MySQL（服务 `MySQL84`）  
2. 主业务：`backend` 设好 `DB_PASSWORD` 后 `mvn spring-boot:run`（8080）  
3. 网关：`gateway` 里 `mvn spring-boot:run`（8088）  
4. 前端只连 8088  

PowerShell 测登录用 `Invoke-RestMethod`，不要用会拆 JSON 的 `curl`。
