## 0. 技术选型（适不适合本组、能不能做完）

原则：**一样的可以用，不适合的才换。** 先看是否服务老师要求（微服务、高并发、多模型风控、贷中贷后），再看是否接得上综设 II 现成代码，最后看 3 个后端在 10 周内能不能稳定演示。

### 0.1 逐项结论

| 候选 | 适不适合本项目 | 可实现性 | 结论 |
|------|----------------|----------|------|
| **Caffeine + Redis 二级缓存** | 适合。产品列表、会话、风控短时去重都是读多写少，直接支撑「高并发」 | **高。** II 已有 Redis，Caffeine 加一个依赖 | **采用（主方案）** |
| Redis 空值短 TTL（防乱打 ID） | 适合，场景小 | **很高。** 十几行 | **采用（顺手做）** |
| 互斥锁防击穿 + TTL 抖动 | 课设没有热点 Key 被打穿的流量 | 中。难演示出真实效果 | **不做** |
| **RabbitMQ + 延迟队列** | **最适合。** 贷后催收要「逾期后再过一段时间升级」，是业务需求 | **高。** Spring AMQP + 一个容器 | **采用（主方案）** |
| Kafka 多 Topic | 能撑事件流，但本组没有日志/大数据消费 | 中偏低。排错容易吃一周 | **不采用**（因为重，不是因为别人用了） |
| **按域垂直拆库** loan / risk / ops | **最适合微服务。** 三后端分域，库跟着服务走 | **高。** 同一 MySQL 三个 schema | **采用（主方案）** |
| ShardingSphere 水平分 8 库 | 适合单表千万行。本组数据量不够，还和按服务拆打架 | **低。** 配错则周五全挂 | **不采用** |
| **申请评分卡 + 规则链 + 行为分插件** | **最适合「多模型」。** 申请看资质，贷中贷后看还款行为 | **高。** II 已有评分卡和规则 | **采用（主方案）** |
| 评分卡版本 + 特征快照回放 | 适合可解释风控和安全审计 | **高。** 评估时多写一张快照表 | **采用** |
| FastAPI + WOE + 逻辑回归 + 随机森林 | 工业合理，但无标注样本，模型无法验证 | **低。** 多一门语言、多一个容器 | **不采用** |
| **真实爬公开网页：LPR + 法院/信用中国主动公示的失信信息** | **适合。** 失信被执行人本来就是法院对社会公示的风险信息，个贷风控有权核验；LPR 服务定价与宏观环境 | **高。** II 已有 Jsoup + HttpClient | **采用（主方案）** |
| 个人征信报告、运营商详单、银行卡流水 | 不是主动公示，也没有课设授权接口 | — | **禁止** |
| 绕过验证码/反爬、对全国执行库做批量搬运 | 公示允许「查阅」，不等于允许打爆接口或绕过防护 | — | **禁止** |
| II 本地演示 HTML（征信/运营商表） | 个人征信类特征的降级，不主讲 | 已有 | **保留为降级** |
| 双主双从 | 不是本阶段功能点 | 低 | **不采用** |
| **Gateway 限流 + 审计 + 角色权限** | 适合「安全管理」+ 高并发保护 | **高。** II 已有 JWT 和管理员角色 | **采用** |

### 0.2 最终技术栈（全组共用底座）

```
微服务：Gateway + loan-service + risk-service + platform-service
数据：  MySQL 三 schema（loan_db / risk_db / ops_db）+ Redis
缓存：  Caffeine(L1) → Redis(L2) → DB；空值短 TTL；风控结果短时去重
消息：  RabbitMQ（业务事件 + 催收延迟队列）
风控：  申请评分卡（版本化）+ 规则链 + 行为分插件 + 快照回放
数据源：真实爬公开页（LPR + 失信公示）+ 库内用户特征；II 演示 HTML 仅降级
安全：  JWT + 网关限流 + 审计日志 + 角色（审批员/管理员/客服）
部署：  Docker Compose 多服务
压测：  开关缓存对比、重复申贷去重次数、延迟队列到期误差
```

和优秀组可以重叠：**Redis、Docker、评分卡、爬虫、限流**。不采用 Kafka / 水平分片 / 训练机器学习，是因为对本组可实现性不够。

## 3. 三个后端的技术栈与工作边界

三人共用 Java 21 + Spring Boot 3.2，代码与职责互不交叉。

### 3.1 后端-信贷 · 熊梓伊（loan-service）

**一句话：** 把综设 II 的主业务从单体里拆出来，保证「注册 → 申贷 → 审批 → 合同 → 放款 → 还款」账不错、状态不乱。

**你要用的技术：**

| 技术 | 用来干什么 |
|------|------------|
| Spring Boot 3.2 + Java 21 | 服务本体 |
| Spring Data JPA + MySQL（第 9 周起连 `loan_db`） | 用户、产品、申请、合同、放款、还款计划、还款流水 |
| Spring Security + JWT（II 已有，你接着改） | 登录注册；JWT 里带 `APPROVER` / `ADMIN` / `CS` 角色 |
| Spring Validation + 状态机（枚举 + 合法流转表） | 申请状态：待审 / 拒绝 / 通过 / 已放款 / 已结清 |
| OpenFeign 或 `RestTemplate` | 申贷后调用风控 `POST /api/risk/assess`，只接收 decision，不解析分箱 |
| Spring AMQP（生产者） | 发出 `loan.applied` / `loan.repaid` / `loan.overdue`，队列由平台声明 |
| 库表唯一约束 | 放款幂等（II 已有思路，继续用数据库校验，不上分布式锁） |

**你要完成的工作：**

- 认领 II 包：`modules/user`、`auth`、`product`、`loanapplication`、`repay`、`Contract*`
- 产品增加 `CONSUME / GENERAL`，申请增加 `usage`、`channelId`、`fastTrack`
- 提供前端要的全部信贷 API；额度变更只开放 `PATCH /api/loans/{id}/limit` 给平台
- **不写** 评分卡公式、爬虫、Gateway、Redis 缓存切面、催收表

**注意：** 主链路在信贷服务上，周五联调依赖本模块先通。

### 3.2 后端-风控 · 岳炜杰（risk-service）

**一句话：** 在 II 评分卡和爬虫上做成「多模型、可解释、可回放」的决策服务，满足老师「多模型智能风控」。

**你要用的技术：**

| 技术 | 用来干什么 |
|------|------------|
| Spring Boot 3.2 + Java 21 | 服务本体 |
| 策略接口 `RiskEngine` + `@Order` 规则链（II 已有） | 申请评分卡、硬性规则、行为分三个插件可开关 |
| `SimpleScoringCardEngine` 升级 | 增加 `cardVersion`、原因码（如 `CREDIT_LOW`、`OVERDUE_HIGH`、`FAST_TRACK`） |
| Jsoup **真实 HTTP** + `t_external_data_cache` | 爬 LPR 公示页 + **法院/信用中国已主动公开的失信名单或公告**；robots.txt、限速、可识别 UA；不绕验证码 |
| `FeatureSnapshot` 落库 | 每次评估把当时特征存下来，供回放 |
| Redis（只用去重 Key） | `userId + productId + 金额桶` 两分钟内不重复计分 |
| Spring Data JPA + MySQL（第 9 周起连 `risk_db`） | `risk_reports`、快照表、外部数据缓存 |
| Spring AMQP（生产者，第 6 周） | 发出 `risk.decided`；消费侧按 `applicationId` 幂等 |
| 纯 Java 行为分（不要 Python / FastAPI） | 用历史逾期次数、最近是否足额还款打第二模型；新用户给中性分 |

**你要完成的工作：**

- 认领 II 包：`modules/risk`、`modules/crawler`
- 对外只提供：`POST /assess`、`POST /replay/{reportId}`、`POST /reevaluate`、`GET /features/{userId}`
- 融合：申请卡 + 规则 + **LPR + 失信公示命中** +（可选）行为分 → 一份 `RiskReportDTO`
- 回放：只用快照重算，不读最新爬虫；关掉行为分时报告结构仍完整
- **不写** 申请状态、合同、放款、还款入账、网关、拆库脚本

**注意：** 第 1 周必须先把评估接口形状交给信贷，否则无法对接。

#### 爬虫怎么做才合法、才算「真爬」（风控必读）

法院、信用中国等**主动向社会公示**的失信被执行人信息，属于公开风险信息，用于贷前核验**不违法**。不能做的是：爬个人征信/运营商这类非公示数据，以及**绕过官网验证码、对全国执行库做批量搬运**。

| 可以 | 不可以 |
|------|--------|
| 中级法院、信用中国、地方政府已发布的**失信名单/公告 HTML** | 个人征信报告、运营商话单、银行卡流水 |
| 央行 LPR 等利率公示页 | 登录后才能看的页面 |
| 按申请人已注册姓名做**命中核对**（用户使用本系统即同意核验公示信息） | 伪造 UA、打码平台、代理池去撞全国查询接口 |
| 低频、标明身份、遵守 robots.txt | robots 明确 Disallow 仍强爬 |

**本阶段两个真实 HTTP 源：**

1. **失信公示（主风险源）**  
   优先选**不设验证码、直接出 HTML 名单或公告**的页面，例如地方中级人民法院、地方「信用中国」、市政府对失信被执行人的定期公示。  
   字段：`dishonest_hit`（是否命中）、`dishonest_name`（公示名，可脱敏展示）、`court_name`、`publish_date`、`case_no`（页面有才存）。  
   匹配规则：用申请人注册姓名（及身份证后 4 位，若公示里有）与名单比对，命中则规则链硬拒，原因码 `DISHONEST_PUBLIC`。  
   全国执行信息公开网查询页若有验证码，**不要破解**；改用上述静态公示页。课设要的是「真爬公示 + 能融合」，不是打全国库。

2. **LPR（宏观源）**  
   中国人民银行货币政策司 LPR 栏目，或货币网/地方金融办转载公告。  
   字段：`lpr_1y`、`lpr_5y`、`lpr_publish_date`。评分卡加「市场利率环境」维，原因码 `LPR_HIGH` / `LPR_OK`。  
   候选：`https://www.pbc.gov.cn/zhengcehuobisi/125207/125213/125440/3876551/`（以当时可访问且 robots 允许为准）。

**工程要求（改 II 的 `DataCrawlerService`）：**

- 对上述 URL 发真实 HTTP，不再把 classpath HTML 当主路径
- 先读 `robots.txt`；UA 写课程项目名 + 邮箱
- 每源间隔 10～30 秒，超时 10 秒；名单页只拉选定的公示 URL，不跟全站链接爬虫
- 失败保留上次成功缓存，报告标 `stale=true`
- 不登录、不打码、不走验证码接口

**II 本地 HTML：** `demo-credit.html` / `demo-telecom.html` 仅作征信类字段降级，答辩主讲「失信公示命中 + LPR」，不主讲末位模拟表。

**进快照与回放：** 每次评估写入当时的失信命中结果和 LPR；回放不重新访问外网。

**代码落点：** `modules/crawler/`（`DataCrawlerService`、定时任务、`POST /api/admin/crawler/run`）；`modules/risk/datasource/` 新增失信适配器。`crawler/crawl_external_data.py` 可作同一 URL 的校验脚本。

### 3.3 后端-平台 · 薛雨宸（gateway + platform-service）

**一句话：** 把微服务跑起来，并用缓存、消息、拆库、限流撑住「高并发 + 贷中贷后 + 获客客服 + 安全」。

**你要用的技术：**

| 技术 | 用来干什么 |
|------|------------|
| Spring Cloud Gateway（前期可用 Nginx 顶上） | 统一入口 `/api/**`，转给三个服务 |
| Caffeine | 进程内 L1，缓存产品列表，TTL 短 |
| Redis（II 已有容器） | L2 缓存；空值短 TTL；`GET /api/ops/cache-stats` 统计 L1/L2/DB |
| RabbitMQ + Spring AMQP | 业务交换机；催收 **延迟队列**（演示 1～2 分钟后进 L1，再超时升 L2） |
| Docker Compose | 维护 mysql / redis / rabbitmq / gateway / 三服务一键启动 |
| MySQL 三 schema | 第 9 周建 `loan_db` / `risk_db` / `ops_db`，给另外两人连接串 |
| Spring Data JPA + `ops_db` | 审计日志、催收任务、工单、FAQ、渠道统计、预警 |
| Gateway 过滤器 | 全局限流（登录/申贷）；把请求写入审计（路径 + userId + 时间） |
| OpenFeign / HTTP | 调风控 `reevaluate` 生成贷中预警，**不自己算分** |

**你要完成的工作：**

- 第 1～9 周偏基建：网关、二级缓存、RabbitMQ、三库
- 第 8、10 周偏业务扩展：延迟催收、贷中监控汇总、获客漏斗、客服工单、限流审计
- 第 11～12 周出压测数字（JMeter 或 wrk，开关缓存对比）
- **不写** 评分卡分箱、还款入账、申请状态机

**注意：** 第 6 周 RabbitMQ、第 9 周三库是全组节点，这两周不能拖。

### 3.4 两个前端的技术栈

- **邢芙（APP）：** uni-app + Vue3 + `request.js`（Bearer Token）。最终交付可安装 APK。HBuilderX「发行 → 原生 App-云打包 → Android」，步骤见 `apps/uni-client/README-Android打包.md`。
- **钟妮（Web）：** Vue3 + Vite + Axios。同一工程三个工作台（审批员 / 管理员 / 客服）。

### 3.5 契约与禁止（并行底线）

| 契约 | 提供方 | 使用方 |
|------|--------|--------|
| 登录 / 注册（可带 `channelId`） | 信贷 | 两前端、网关 |
| `LoanApplicationDTO` | 信贷 | 风控、平台、前端 |
| `POST /api/risk/assess` → `RiskReportDTO` | 风控 | 信贷 |
| `POST /api/risk/replay/{reportId}` | 风控 | Web、平台 |
| `POST /api/risk/reevaluate` | 风控 | 平台 |
| 事件 `loan.applied` / `loan.repaid` / `loan.overdue` / `risk.decided` | 信贷或风控生产 | 其余消费 |
| 延迟队列 `collection.l1` / `collection.l2` | 平台 | 催收 |
| `GET /api/products`（走二级缓存） | 信贷写库，平台做缓存 | 两前端 |
| 工单 / FAQ / 审计 / 催收表 | 平台独占 | 两前端 |

信贷不写报告和快照；风控不改申请状态和账务；平台不改分箱和行为分。跨域只调 API 或收消息。

**每周节奏：** 周一贴接口增量 → 周四自测 → 周五全员验收，只修阻断缺陷。

### 第 10 周 — 贷中、贷后、获客、客服、安全一次齐

**本周目标：** 老师点名的扩展功能都能点开。

**邢芙（APP）— 借款端剩余入口补齐。**  
贷中/额度页、逾期提醒、邀请注册（带自己的 channelId）、客服工单提交、FAQ 列表。四个入口都能进、都能打到对应 API。不要求美观到终版。

**钟妮（Web）— 三个账号进三个工作台。**  
审批员：待审、报告、回放、合同、放款。管理员：产品、渠道统计、贷中监控（在贷笔数、预警数、重评记录）、审计。客服：工单队列、回复、FAQ 维护。换三个 JWT，侧栏菜单必须不同。

**熊梓伊（信贷）— 额度只留一个补丁口，JWT 带齐三角色。**  
`PATCH /api/loans/{id}/limit` 供平台写建议额度；其他人不要直接改表。管理员登录签发 `ADMIN`，审批员 `APPROVER`，客服 `CS`（用户端仍是普通 USER）。种子三个后台账号给 Web。

**岳炜杰（风控）— 重评要给出建议额度。**  
`reevaluate` 增加 `suggestLimit`（可按行为分简单打折）。仍然不改信贷库；平台收到建议后再调信贷 PATCH。

**薛雨宸（平台）— 扩展功能收口到你这一个服务。**  
① 调重评，写预警表，监控汇总 API（在贷/预警/逾期，在贷数可调信贷只读接口）② 催收工作台：跟进、结清标记 ③ 渠道转化（注册/申贷/放款计数）④ 工单 CRUD + FAQ ⑤ Gateway 限流（登录或申贷超阈值返回 429）。每块最小可用即可，不要做深。
