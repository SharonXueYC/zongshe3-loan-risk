# 综合贷款管理系统 - 后端核心业务场景总结

## 文档说明
本文档总结概括了综合贷款管理系统后端需要支撑的核心业务场景，并详细描述了后端需要完成的任务。

---

## 一、核心业务场景概览

后端系统需要支撑以下**8大核心业务场景**：

1. **用户认证与授权场景**
2. **用户生命周期管理场景**
3. **贷款申请与审核场景**
4. **合同与放款管理场景**
5. **产品管理场景**
6. **数据统计与分析场景**
7. **系统配置管理场景**
8. **安全与风控场景**

---

## 二、核心业务场景详细说明

### 场景一：用户认证与授权场景

**业务描述：** 支持用户和管理员的安全登录认证，提供多种登录方式，实现基于JWT的无状态身份认证和权限控制。

**后端需要完成的任务：**

#### 1.1 用户注册认证
- **任务描述：** 处理新用户注册请求，确保用户信息的唯一性和安全性
- **需求描述：** 系统需要提供用户注册功能，验证手机号和身份证号唯一性，创建用户账号并设置默认信用分，同时发送验证码完成注册流程
- **具体工作：**
  - 接收用户注册请求，使用`@Valid`注解验证请求参数的格式和完整性（手机号、身份证号、用户名、密码等）
  - 调用Repository层检查手机号是否已存在于数据库中，防止重复注册
  - 调用Repository层检查身份证号是否已被其他用户使用，确保身份唯一性
  - 如果信息已存在，返回明确的错误提示（如"手机号已注册"、"身份证号已注册"）
  - 为新用户生成唯一的UUID作为用户ID，确保全局唯一性
  - 使用BCrypt算法对用户密码进行加密存储，确保密码安全
  - 为新用户设置默认信用分（从系统配置读取，默认500分），初始化用户信用体系
  - 设置用户初始状态为正常（status=1），允许用户正常使用系统
  - 调用短信服务发送验证码（实际实现中可集成第三方短信服务），将验证码存储到Redis，设置5分钟过期时间
  - 使用`@Transactional`注解确保用户创建和验证码发送的原子性，如果任何步骤失败则回滚
  - 记录用户注册日志，便于后续审计和问题排查
  - 返回注册结果，包含用户ID和成功提示信息

#### 1.2 登录认证（密码登录/验证码登录/管理员登录）
- **任务描述：** 支持用户和管理员多种方式的登录认证，生成JWT令牌
- **需求描述：** 系统需要支持用户通过手机号密码或验证码登录，支持管理员登录，验证身份和账户状态，生成JWT令牌供后续接口认证使用
- **具体工作：**
  - **用户密码登录：**
    - 接收登录请求，验证请求参数格式（手机号、密码不能为空）
    - 根据手机号从数据库查询用户信息，如果用户不存在则返回"用户不存在"错误
    - 检查用户账户状态，如果账户已被冻结（status=2），返回"账户已冻结"错误，阻止登录
    - 使用BCrypt算法验证用户输入的密码与数据库中存储的加密密码是否匹配
    - 如果密码验证失败，返回"密码错误"提示
    - 密码验证成功后，调用JWT工具类生成JWT令牌，令牌中包含用户ID、手机号等关键信息，设置有效期为2小时
    - 将User实体对象转换为UserDTO对象，对敏感信息进行脱敏处理
    - 记录用户登录日志，包括登录时间、IP地址等信息
    - 返回登录结果，包含JWT令牌、令牌过期时间、用户基本信息（已脱敏）
  - **验证码登录：**
    - 发送验证码阶段：接收发送验证码请求，验证手机号格式，生成6位随机数字验证码，存储到Redis（key: "otp:" + phoneNumber, 过期时间5分钟），调用短信服务发送验证码
    - 验证码登录阶段：接收验证码登录请求，从Redis获取验证码并验证，验证成功后删除验证码，如果用户不存在则自动创建新用户，生成JWT令牌并返回
  - **管理员登录：**
    - 接收管理员登录请求，验证用户名和密码参数
    - 根据用户名从数据库查询管理员信息，如果不存在返回错误
    - 检查管理员账户状态（isActive字段），如果账户被禁用则拒绝登录
    - 使用BCrypt验证管理员密码
    - 生成JWT令牌，令牌中包含管理员ID、用户名、角色（superAdmin、admin、finance、operator）等信息
    - 更新管理员的最后登录时间到数据库
    - 将Admin实体转换为AdminLoginResponse DTO，包含管理员基本信息和权限信息
    - 记录管理员登录日志
    - 返回登录结果，包含令牌和管理员信息

#### 1.5 Token验证与权限控制
- **任务描述：** 在所有需要认证的接口中验证JWT令牌，实现基于角色的权限控制
- **需求描述：** 系统需要在所有需要认证的接口中验证JWT令牌有效性，解析用户身份和角色信息，根据角色权限控制接口访问
- **具体工作：**
  - 从HTTP请求头中提取Authorization字段，获取Bearer token
  - 验证token格式是否正确（必须以"Bearer "开头）
  - 调用JWT工具类验证token的有效性（是否过期、签名是否正确）
  - 从token中解析出用户ID或管理员ID、角色等信息
  - 对于管理员操作，检查管理员角色是否具有执行该操作的权限（如只有superAdmin可以修改系统设置）
  - 如果token无效或权限不足，返回401未授权错误
  - 将解析出的用户信息存储到请求上下文中，供后续业务逻辑使用

### 场景二：用户生命周期管理场景

**业务描述：** 管理用户从注册到注销的完整生命周期，包括用户信息查询、更新、信用分管理、账户状态控制等功能。

**后端需要完成的任务：**

#### 2.1 信息详情查询（用户/申请/产品）
- **任务描述：** 根据ID查询详细信息，对敏感信息进行脱敏处理
- **需求描述：** 系统需要根据ID查询用户、贷款申请或产品的详细信息，对敏感信息进行脱敏处理后返回给前端，并验证用户权限
- **具体工作：**
  - **用户信息查询：**
    - 接收查询请求，从路径参数获取用户ID
    - 可选：从请求头获取token，验证token有效性，确保用户只能查看自己的信息或管理员可以查看所有用户
    - 调用Repository层根据用户ID查询用户实体
    - 如果用户不存在，抛出业务异常或返回明确的错误信息
    - 将User实体转换为UserDTO对象，在转换过程中对敏感信息进行脱敏（手机号、身份证号）
    - 返回脱敏后的用户信息
  - **申请详情查询：**
    - 接收查询请求，从路径参数获取申请ID
    - 调用Repository的`findById()`方法查询申请
    - 如果申请不存在，返回错误
    - 可选：验证用户权限（用户只能查看自己的申请，管理员可以查看所有申请）
    - 将LoanApplication实体转换为LoanApplicationDTO，包含申请基本信息、申请人信息（脱敏）、审核信息等
    - 返回申请详情
  - **产品详情查询：**
    - 接收查询请求，从路径参数获取产品ID
    - 调用Repository的`findById()`方法查询产品
    - 如果产品不存在，返回错误
    - 将Product实体转换为ProductDTO
    - 返回产品详情，包括产品编号、名称、类型、额度范围、期限范围、年利率、产品描述、状态等

#### 2.2 信息更新（用户/产品）
- **任务描述：** 更新用户或产品信息，确保数据的一致性和有效性
- **需求描述：** 系统需要支持用户和管理员更新用户信息，支持管理员更新产品信息，验证更新数据的有效性，检查唯一性约束，确保数据更新的一致性和准确性
- **具体工作：**
  - **用户信息更新：**
    - 接收更新请求，从路径参数获取用户ID，从查询参数或请求体获取要更新的字段（用户名、手机号等）
    - 验证token，确保操作者有权修改该用户信息（用户只能修改自己的信息，管理员可以修改所有用户信息）
    - 调用Repository查询用户，如果用户不存在返回错误
    - 如果要更新手机号，检查新手机号是否已被其他用户使用，确保手机号唯一性
    - 验证更新数据的格式和有效性（如手机号格式、用户名长度等）
    - 更新User实体的相应字段
    - 调用Repository的save方法保存更新，使用`@Transactional`确保数据一致性
    - 记录更新操作日志
    - 返回更新成功结果
  - **产品更新：**
    - 接收更新请求，获取产品ID和要更新的字段
    - 验证管理员token和权限
    - 调用Repository查询产品，如果产品不存在返回错误
    - 验证更新数据的有效性（产品名称、类型、额度范围、期限范围、利率等验证规则）
    - 更新Product实体的相应字段
    - 保存更新到数据库
    - 记录更新日志
    - 返回更新结果

#### 2.3 用户信用分管理
- **任务描述：** 管理用户信用分，支持信用分查询、更新，并根据信用分计算可用贷款额度
- **需求描述：** 系统需要管理用户信用分，支持管理员更新信用分，根据用户信用分计算可用贷款额度，并提供额度查询功能
- **具体工作：**
  - **信用分查询：** 在查询用户信息时返回当前信用分
  - **信用分更新：** 
    - 接收管理员发起的信用分更新请求
    - 验证管理员权限（只有特定角色的管理员可以修改信用分）
    - 验证信用分范围（如0-1000分）
    - 更新用户信用分并保存
    - 记录信用分变更日志，包括变更前分值、变更后分值、变更原因、操作人
  - **额度计算：**
    - 根据用户信用分计算可用贷款额度（业务规则：如信用分*100，或根据信用分区间设定不同额度）
    - 从系统配置读取最大贷款额度限制
    - 取计算值和系统限制的较小值作为最终可用额度
    - 返回额度信息，包括可用额度、当前信用分、额度计算说明

#### 2.4 状态管理（用户/产品）
- **任务描述：** 支持启用和禁用用户账户或产品，控制其在系统中的可用性
- **需求描述：** 系统需要支持管理员启用或禁用用户账户和产品，控制用户系统访问权限和产品可用性，记录状态变更操作日志
- **具体工作：**
  - **用户账户状态管理：**
    - 接收状态更新请求，获取用户ID和新的状态值（1-正常，2-冻结）
    - 验证管理员token和权限（只有管理员可以修改用户状态）
    - 验证状态值的有效性（必须是1或2）
    - 查询用户，如果用户不存在返回错误
    - 更新用户状态字段
    - 保存更新到数据库
    - 如果状态变更为冻结，可选：记录冻结原因、冻结时间、操作人
    - 记录操作日志
    - 返回操作结果
  - **产品状态管理：**
    - 接收状态更新请求，获取产品ID和新的状态（active/inactive）
    - 验证管理员权限
    - 查询产品并更新状态
    - 保存更新
    - 记录状态变更日志
    - 返回操作结果

#### 2.5 列表查询与筛选（用户/申请/产品）
- **任务描述：** 支持多条件筛选和分页查询列表数据
- **需求描述：** 系统需要支持查询用户列表、贷款申请列表和产品列表，提供按状态、类型、关键词等多条件筛选功能，支持分页查询，对敏感信息进行脱敏处理
- **具体工作：**
  - **用户列表查询：**
    - 接收查询请求，获取筛选参数（状态、角色、关键词等）
    - 验证管理员token和权限
    - 根据筛选条件构建查询（状态筛选、关键词模糊查询），支持组合查询
    - 支持分页查询（使用Spring Data JPA的Pageable接口）
    - 将查询结果转换为UserDTO列表，对所有用户的敏感信息进行脱敏处理
    - 返回用户列表和总数
  - **贷款申请列表查询：**
    - 用户查询自己的申请：从token解析用户ID，调用`findByUserIdOrderByApplyTimeDesc()`方法查询，按申请时间倒序排列，转换为DTO列表返回
    - 管理员查询所有申请：获取筛选参数（status、loanType、search），根据筛选条件构建查询（状态筛选、类型筛选、关键词模糊查询），支持分页查询，转换为DTO列表返回
  - **产品列表查询：**
    - 接收查询请求，获取筛选参数（type-类型、status-状态、search-关键词）
    - 验证管理员token
    - 根据筛选条件构建查询（类型筛选、状态筛选、关键词模糊查询），支持组合查询
    - 支持分页查询
    - 将Product实体列表转换为ProductDTO列表
    - 返回产品列表和总数

#### 2.6 贷款资格检查
- **任务描述：** 根据用户信用分判断用户是否符合贷款条件
- **需求描述：** 系统需要根据用户当前信用分与系统配置的最低信用分要求进行比较，判断用户是否符合贷款条件
- **具体工作：**
  - 接收资格检查请求，获取用户ID
  - 查询用户信息，获取用户当前信用分
  - 从系统配置读取最低信用分要求（minCreditScoreForLoan，默认450分）
  - 比较用户信用分与最低要求：`creditScore >= minCreditScoreForLoan`
  - 返回检查结果，包括是否符合条件、当前信用分、最低要求、提示信息

### 场景三：贷款申请与审核场景

**业务描述：** 处理用户提交的贷款申请，实现完整的申请-审核-放款流程管理，包括申请创建、状态管理、审核处理等功能。

**后端需要完成的任务：**

#### 3.1 贷款申请提交
- **任务描述：** 接收用户提交的贷款申请，验证申请信息的有效性，创建申请记录
- **需求描述：** 系统需要接收用户提交的贷款申请，验证用户贷款资格和申请信息有效性，生成唯一申请单号，创建申请记录并保存到数据库
- **具体工作：**
  - 接收申请请求，从请求头解析JWT token获取用户ID
  - 验证token有效性，确保用户已登录
  - 调用Repository查询用户，检查用户状态（是否冻结）
  - 调用UserService的`checkLoanQualification()`方法检查用户是否符合贷款条件（信用分是否达标）
  - 验证申请金额是否在系统配置的范围内（min-loan-amount到max-loan-amount之间）
  - 如果指定了产品ID，查询产品信息，验证：
    - 申请金额是否在产品允许的额度范围内（minAmount到maxAmount）
    - 申请期限是否在产品允许的期限范围内（minTerm到maxTerm）
  - 验证其他申请信息（如还款方式是否有效、利率是否合理等）
  - 生成唯一的申请单号（格式如：LA-20231221-001，包含日期和序号）
  - 创建LoanApplication实体对象：
    - 设置申请单号
    - 关联用户（通过User实体）
    - 设置申请金额、期限、类型、还款方式、利率
    - 设置申请说明（description字段）
    - 设置状态为pending（待审核）
    - 设置申请时间为当前时间
  - 使用`@Transactional`注解确保申请创建的原子性
  - 调用Repository的save方法保存申请记录
  - 记录申请提交日志
  - 返回申请结果，包含申请ID、申请单号、提交时间、提示信息

#### 3.4 贷款申请审核（通过/拒绝）
- **任务描述：** 管理员审核贷款申请，支持审核通过或拒绝，更新申请状态并记录审核信息
- **需求描述：** 系统需要支持管理员审核贷款申请，可以审核通过或拒绝申请，验证申请状态为待审核，更新申请状态并记录审核备注、时间和操作人
- **具体工作：**
  - **审核通过：**
    - 接收审核请求，从路径参数获取申请ID，从请求体获取审核备注（可选）
    - 验证管理员token和权限（检查管理员是否有审核权限）
    - 调用Repository查询申请，如果申请不存在返回错误
    - 检查申请状态，如果不是pending（待审核）状态，返回"申请状态不正确"错误
    - 更新申请状态为"approved"（已通过）
    - 设置审核备注（如果有）
    - 设置审核时间为当前时间
    - 可选：从token中获取管理员ID，记录审核人信息
    - 使用`@Transactional`确保状态更新的原子性
    - 保存更新到数据库
    - 可选：触发后续业务流程（生成电子合同、创建还款计划、发送审核通过通知）
    - 记录审核操作日志
    - 返回审核结果
  - **审核拒绝：**
    - 接收拒绝请求，获取申请ID和拒绝原因（必填）
    - 验证拒绝原因不能为空
    - 验证管理员token和权限
    - 查询申请，检查状态是否为pending
    - 更新申请状态为"rejected"（已拒绝）
    - 设置审核备注为拒绝原因
    - 设置审核时间
    - 保存更新
    - 可选：发送拒绝通知给用户，告知拒绝原因
    - 记录操作日志
    - 返回拒绝结果

#### 3.6 申请状态流转管理
- **任务描述：** 管理申请状态的流转，确保状态变更的合法性和可追溯性
- **需求描述：** 系统需要定义和管理贷款申请的状态流转规则，确保状态变更的合法性，记录所有状态变更的完整日志，提供状态变更历史查询
- **具体工作：**
  - 定义申请状态流转规则：
    - pending（待审核）→ approved（已通过）或 rejected（已拒绝）
    - approved（已通过）→ disbursed（已放款）
    - 不允许逆向流转

  - 记录每次状态变更的日志，包括变更前状态、变更后状态、变更时间、操作人、变更原因
  - 提供状态变更历史查询接口

#### 4.4 还款计划生成与逾期处理
- **任务描述：** 在合同签署或放款完成后自动生成还款计划，并定时检测和处理逾期还款，确保还款计划准确性和逾期处理的及时性
- **需求描述：** 系统需要根据贷款金额、期限、利率和还款方式自动生成还款计划表，定时检测逾期还款情况，自动计算逾期利息和罚息，更新还款计划状态，发送逾期提醒
- **具体工作：**
  - **还款计划生成：**
    - 在合同双方签署完成或放款完成后自动触发还款计划生成（或在合同生成后手动触发）
    - 接收生成请求，从路径参数获取合同ID，或从合同签署/放款流程中自动获取
    - 验证合同状态，只有已签署或已放款的合同才能生成还款计划
    - 检查是否已存在还款计划，如果已存在则不允许重复生成（或支持重新生成）
    - 查询合同关联的贷款申请信息，获取：
      - 贷款金额（loanAmount）
      - 贷款期限（loanTerm，单位：月）
      - 利率（从申请或产品中获取）
      - 还款方式（等额本息、等额本金、先息后本、一次性还本付息等）
    - 根据还款方式计算每期还款金额和还款日期：
      - **等额本息：** 使用公式计算每期还款金额：`M = P * [r(1+r)^n] / [(1+r)^n - 1]`，其中M为每期还款额，P为贷款本金，r为月利率，n为还款期数
      - **等额本金：** 每期本金固定，利息递减，每期还款金额 = 本金/期数 + (本金-已还本金累计)*月利率
      - **先息后本：** 前期只还利息，最后一期还本金+利息
      - **一次性还本付息：** 只有一期，到期还本金+总利息
    - 计算每期还款日期：
      - 从放款日期（或合同签署日期）开始计算
      - 根据还款周期（按月）计算每期的还款日期
      - 如果某期还款日期为周末或节假日，可选：自动调整到最近的工作日
    - 为每一期创建RepayPlan实体对象：
      - 关联合同（通过contract字段）
      - 设置还款日期（repayDate）
      - 设置还款金额（repayAmount，包含本金+利息）
      - 可选：分别记录本金金额和利息金额
      - 设置还款状态为0（待还款）或1（未到期）
      - 设置期数（第几期）
    - 使用`@Transactional`确保还款计划生成的原子性
    - 批量保存所有期数的还款计划到数据库（使用批量插入优化性能）
    - 可选：发送还款计划生成通知给用户，包含还款计划详情
    - 记录还款计划生成日志
    - 返回生成结果，包含还款计划总数、总还款金额、首期还款日期等信息
  - **逾期检测与处理（定时任务）：**
    - 使用Spring的`@Scheduled`注解创建定时任务，每天执行一次（如每天凌晨2点执行）
    - **逾期检测逻辑：**
      - 查询所有状态为"待还款"（状态0）且还款日期已过期的还款计划
      - 使用@Query查询条件：`repayStatus = 0 AND repayDate < CURRENT_DATE`
      - 对每个逾期的还款计划：
        - 计算逾期天数：当前日期 - 还款日期
        - 从系统配置读取逾期罚息率（overduePenaltyRate，如日利率0.05%）
        - 计算逾期罚息：逾期本金 * 逾期天数 * 逾期罚息率
        - 可选：计算复利（如果系统支持）
        - 更新还款计划：
          - 将还款状态更新为2（已逾期）
          - 可选：记录逾期天数、逾期罚息金额
          - 可选：更新总还款金额 = 原还款金额 + 逾期罚息
        - 保存更新到数据库
        - 可选：更新用户信用分（扣除逾期扣分，如逾期1天扣5分）
    - **逾期提醒：**
      - 对逾期用户发送逾期提醒通知（短信、站内消息、邮件等）
      - 通知内容包含：合同编号、逾期期数、逾期天数、逾期金额、逾期罚息、提醒尽快还款
      - 可选：根据逾期天数设置不同的提醒频率（逾期1-3天每天提醒，逾期3-7天每2天提醒，逾期7天以上每天提醒）
    - 记录逾期处理日志，包括处理的还款计划数量、逾期总金额等
  - **还款计划查询接口：**
    - 接收查询请求，从路径参数获取合同ID或还款计划ID
    - 验证用户权限（用户只能查询自己合同的还款计划，管理员可以查询所有）
    - 查询还款计划列表，按期数排序
    - 返回还款计划详情，包括每期的还款日期、还款金额、还款状态、逾期信息（如有）等

  - 组装统计数据Map
  - 返回统计数据：`{total: 100, pending: 25, approved: 60, rejected: 15, todayNew: 5}`

#### 6.2 数据统计与图表（申请趋势/产品销售/状态分布）
- **任务描述：** 按不同维度统计贷款申请数据，生成图表数据供前端可视化展示
- **需求描述：** 系统需要按时间维度统计申请趋势，按产品统计销售情况，按状态统计分布情况，组装成不同格式的图表数据供前端绘制折线图、柱状图、饼图
- **具体工作：**
  - **申请趋势统计：**
    - 接收趋势统计请求，可选：获取时间范围参数（如最近7天、最近30天、最近一年）
    - 验证管理员token
    - 查询指定时间范围内的所有申请
    - 按时间维度（月或日）分组统计，使用@Query或Java代码按申请时间分组，分别统计每个时间段的pending、approved、rejected数量
    - 组装数据格式：时间轴数组和各状态的数量数组
    - 返回趋势数据，供前端绘制折线图
  - **产品销售统计：**
    - 接收销售统计请求，验证管理员token
    - 查询所有产品
    - 对每个产品，使用@Query按产品类型或产品ID分组统计关联的贷款申请数量
    - 组装数据格式：产品名称数组和申请数量数组
    - 返回销售数据，供前端绘制柱状图
  - **状态分布统计：**
    - 接收状态分布统计请求，验证管理员token
    - 统计各状态的申请数量（调用`findByStatus()`分别统计已通过、待审核、已拒绝数量）
    - 组装数据格式：状态名称和数量的键值对
    - 返回状态分布数据，供前端绘制饼图

#### 6.3 数据导出功能（可选）
- **任务描述：** 支持将统计数据导出为Excel或CSV格式
- **需求描述：** 系统需要支持将统计数据导出为Excel或CSV格式文件，供管理员下载和分析
- **具体工作：**
  - 接收导出请求，获取要导出的数据类型和时间范围
  - 查询相应的统计数据
  - 使用Apache POI或EasyExcel库生成Excel文件
  - 设置HTTP响应头，指定文件类型和文件名
  - 将文件流写入响应体
  - 返回文件供用户下载

### 场景七：系统配置管理场景

**业务描述：** 管理系统配置参数，支持配置的查询和更新，确保系统参数的可配置性和灵活性。

**后端需要完成的任务：**

#### 7.1 系统设置管理（查询/更新/重置）
- **任务描述：** 管理系统配置参数，支持查询、更新和重置操作
- **需求描述：** 系统需要从数据库或配置文件读取系统配置参数，支持超级管理员更新配置参数和重置为默认值，验证配置有效性，记录配置变更日志
- **具体工作：**
  - **系统设置查询：**
    - 接收查询请求，验证管理员token和权限
    - 从数据库的system_settings表读取配置，或从application.properties配置文件读取
    - 如果使用数据库存储：查询system_settings表的所有配置项，将配置项组装成SystemSettingsDTO对象
    - 如果使用配置文件：从ApplicationProperties类读取配置值，组装成DTO对象
    - 返回配置信息，包括最小/最大贷款金额、默认/最低信用分、贷款期限选项、逾期罚息率等
  - **系统设置更新：**
    - 接收更新请求，获取要更新的配置参数
    - 验证管理员token和权限（只有superAdmin角色可以修改系统设置）
    - 验证配置值的有效性（金额必须为正数、最大金额必须大于最小金额、信用分范围、利率范围等）
    - 如果使用数据库存储：更新system_settings表中对应配置项的值并保存
    - 如果使用配置文件：更新application.properties文件或使用Spring Cloud Config实现动态配置刷新
    - 可选：使用@RefreshScope实现配置热更新（无需重启应用）
    - 记录配置变更日志，包括变更前值、变更后值、操作人、变更时间
    - 返回更新结果
  - **系统设置重置：**
    - 接收重置请求，验证superAdmin权限
    - 将配置参数重置为系统默认值
    - 保存到数据库或配置文件
    - 记录重置操作日志
    - 返回重置结果

### 场景八：安全与风控场景

**业务描述：** 保障系统安全，实现数据加密、敏感信息脱敏、异常处理、日志记录等安全机制。

**后端需要完成的任务：**

#### 8.1 数据加密与安全存储
- **任务描述：** 对敏感数据进行加密存储，确保数据安全
- **需求描述：** 系统需要使用BCrypt算法对用户和管理员密码进行加密存储，确保密码在数据库中存储的是加密哈希值而非明文
- **具体工作：**
  - 使用BCrypt算法对用户密码进行加密存储，BCrypt具有自动加盐和可配置的加密强度
  - 对管理员密码同样使用BCrypt加密
  - 确保密码在数据库中存储的是加密后的哈希值，而不是明文
  - 在密码验证时，使用BCrypt的验证方法比较输入的密码和存储的哈希值
  - 对于其他敏感数据（如身份证号），可以考虑使用AES加密存储（可选）

#### 8.2 敏感信息脱敏处理
- **任务描述：** 在返回给前端的数据中对敏感信息进行脱敏，保护用户隐私
- **需求描述：** 系统需要在返回给前端的数据中对手机号和身份证号等敏感信息进行脱敏处理，保护用户隐私，同时提供统一的脱敏工具类
- **具体工作：**
  - 在将User实体转换为UserDTO时，对敏感信息进行脱敏：
    - 手机号：保留前3位和后4位，中间用****替代（如：138****1234）
    - 身份证号：保留前3位和后4位，中间用*替代（如：110***********5678）
  - 在返回申请列表时，对申请人的手机号和身份证号进行脱敏
  - 在日志记录中，对敏感信息进行脱敏，避免敏感信息泄露到日志文件
  - 提供统一的脱敏工具类，便于复用

#### 8.3 异常处理与参数验证
- **任务描述：** 统一处理系统异常和验证请求参数，返回标准格式的错误响应
- **需求描述：** 系统需要实现全局异常处理器统一捕获和处理各种异常，在所有接口中使用@Valid注解验证请求参数，返回标准格式的错误响应，记录异常日志但不向客户端暴露敏感信息
- **具体工作：**
  - **异常处理：**
    - 使用@ControllerAdvice和@ExceptionHandler实现全局异常处理器
    - 捕获不同类型的异常（业务异常、参数验证异常、数据库异常、系统异常），返回相应的错误信息
    - 统一错误响应格式：`{success: false, message: "错误信息", code: "错误代码"}`
    - 记录异常日志，包括异常堆栈、请求信息、用户信息等
    - 对于生产环境，不向客户端返回详细的异常堆栈信息
  - **参数验证：**
    - 使用@Valid注解触发DTO的验证规则
    - 在DTO类中使用验证注解（@NotNull、@NotBlank、@Size、@Min、@Max、@Pattern、@Email等）
    - 自定义验证注解（如验证手机号格式、身份证号格式）
    - 在Controller层使用@Valid验证请求参数
    - 验证失败时返回详细的错误信息，指出哪些字段验证失败及失败原因

#### 8.4 日志记录与事务管理
- **任务描述：** 记录关键操作的日志，管理数据库事务确保数据一致性
- **需求描述：** 系统需要记录所有关键业务操作的日志，配置日志级别和输出位置，在关键业务操作方法上使用@Transactional注解管理数据库事务，确保数据操作的原子性
- **具体工作：**
  - **操作日志记录：**
    - 使用@Slf4j记录日志
    - 记录关键操作的日志（用户注册、登录、信息更新、贷款申请提交、审核、产品操作、系统设置更新、管理员操作）
    - 日志内容包括操作时间、操作类型、操作用户、操作内容、IP地址等
    - 配置日志级别和输出位置（控制台、文件）
    - 实现日志轮转，避免日志文件过大
  - **事务管理：**
    - 使用@Transactional注解管理数据库事务
    - 在关键业务方法上添加@Transactional（用户注册、贷款申请提交、申请审核、产品创建更新）
    - 配置事务传播行为（通常使用REQUIRED）
    - 配置事务隔离级别（通常使用READ_COMMITTED）
    - 配置回滚规则（哪些异常需要回滚）
    - 确保事务的原子性：要么全部成功，要么全部回滚

#### 7.6 事务管理
- **任务描述：** 确保关键业务操作的数据一致性
- **需求描述：** 系统需要在关键业务操作方法上使用@Transactional注解管理数据库事务，确保数据操作的原子性，配置事务传播行为和隔离级别
- **具体工作：**
  - 使用@Transactional注解管理数据库事务
  - 在关键业务方法上添加@Transactional：
    - 用户注册（用户创建+验证码发送）
    - 贷款申请提交
    - 申请审核（状态更新+日志记录）
    - 产品创建、更新
  - 配置事务传播行为（通常使用REQUIRED）
  - 配置事务隔离级别（通常使用READ_COMMITTED）
  - 配置回滚规则（哪些异常需要回滚）
  - 确保事务的原子性：要么全部成功，要么全部回滚

#### 8.5 跨域资源共享（CORS）配置
- **任务描述：** 配置CORS策略，允许前端跨域访问API
- **需求描述：** 系统需要配置CORS策略，允许指定域名的前端应用跨域访问API接口，配置允许的HTTP方法、请求头和凭证
- **具体工作：**
  - 创建CorsConfig配置类
  - 配置允许的源（origins）：开发环境允许localhost，生产环境配置实际域名
  - 配置允许的HTTP方法（GET、POST、PUT、DELETE等）
  - 配置允许的请求头（如Authorization、Content-Type）
  - 配置是否允许携带凭证（credentials）
  - 配置预检请求（OPTIONS）的缓存时间

## 三、后端技术架构支撑

### 3.1 三层架构实现
- **Controller层（表现层）：** 接收HTTP请求，验证参数，调用Service层，返回HTTP响应
- **Service层（业务逻辑层）：** 实现业务逻辑，事务管理，数据转换，调用Repository层
- **Repository层（数据访问层）：** 数据库CRUD操作，自定义查询，数据持久化

### 3.2 核心技术组件
- **Spring Boot 3.2.5：** 应用框架，提供自动配置和快速开发能力
- **Spring Data JPA：** 数据持久层框架，简化数据库操作
- **Spring Security：** 安全框架，提供认证和授权
- **JWT（jjwt 0.12.5）：** 无状态身份认证
- **MySQL 8.0+：** 关系型数据库，存储业务数据
- **Redis：** 缓存和会话存储（验证码、会话等）
- **BCrypt：** 密码加密算法
- **Swagger/OpenAPI：** API文档生成

### 3.3 数据模型设计
- **8个核心实体：** User（用户）、Admin（管理员）、LoanApplication（贷款申请）、Product（产品）、Contract（合同）、RepayPlan（还款计划）、DisburseRecord（放款记录）、RiskReport（风控报告）
- **实体关系：** 用户与申请的一对多关系，申请与产品的多对一关系等
- **数据完整性：** 使用外键约束、唯一索引等保证数据完整性

## 四、总结

后端系统需要支撑**8大核心业务场景**，实现**35+个RESTful API接口**。后端需要完成的主要任务包括（已合并相似任务，共22个核心任务）：

1. **用户认证与授权**：支持多种登录方式，实现JWT认证和权限控制
2. **用户管理**：用户信息CRUD、信用分管理、账户状态控制
3. **贷款申请管理**：申请提交、查询、审核、状态流转
4. **合同与放款管理**：电子合同生成、签署与状态同步、放款执行、还款计划生成与逾期处理
5. **产品管理**：产品CRUD、状态管理、关联检查
6. **数据统计**：多维度数据统计、图表数据生成
7. **系统配置**：配置查询、更新、重置
8. **安全机制**：数据加密、脱敏、异常处理、日志记录、事务管理

后端系统采用**三层架构设计**，使用**Spring Boot + Spring Data JPA + Spring Security**技术栈，通过**RESTful API**为前端提供数据服务，确保系统的**安全性、可靠性和可维护性**。
