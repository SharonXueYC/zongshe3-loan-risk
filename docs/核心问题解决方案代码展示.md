## 问题1：CORS跨域配置冲突

### 问题描述
同时配置了多个CORS配置导致冲突，前端请求时出现CORS错误。

### 核心解决代码

**1. CorsConfig.java - 统一的CORS配置**

```java
@Configuration
public class CorsConfig {

    @Value("${cors.allowed-origins:http://localhost:5000,http://localhost:8080,http://localhost:5173,http://localhost:3000,*}")
    private String allowedOrigins;

    @Bean
    public CorsFilter corsFilter() {
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        CorsConfiguration config = new CorsConfiguration();

        // 设置允许的源
        String[] origins = allowedOrigins.split(",");
        for (String origin : origins) {
            config.addAllowedOrigin(origin.trim());
        }

        // 设置允许的方法
        String[] methods = allowedMethods.split(",");
        for (String method : methods) {
            config.addAllowedMethod(method.trim());
        }

        // 设置允许的头部
        String[] headers = allowedHeaders.split(",");
        for (String header : headers) {
            config.addAllowedHeader(header.trim());
        }

        // 允许携带凭证（如cookies）
        config.setAllowCredentials(allowCredentials);
        config.setMaxAge(3600L);

        // 对所有接口应用此配置
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}
```

**2. SecurityConfig.java - 引用CorsConfig配置**

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(AbstractHttpConfigurer::disable)
        .cors(cors -> cors.configure(http))  // ✅ 关键：引用CorsConfig的配置
        .sessionManagement(session ->
            session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth
            // ✅ 关键：预检请求直接放行
            .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
            // ... 其他配置
        );
    return http.build();
}
```

**3. WebConfig.java - 移除重复的CORS配置**

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    
    // ❌ 移除 addCorsMappings 方法，避免配置冲突
    // 只保留静态资源配置
    
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 静态资源配置...
    }
}
```

### 解决要点
- **统一配置源**：只在一个地方（CorsConfig）配置CORS
- **Security集成**：使用`cors.configure(http)`让Spring Security使用CorsConfig的配置
- **预检请求放行**：明确放行OPTIONS预检请求
- **移除冲突配置**：删除WebConfig中的CORS配置，避免重复

## 问题2：Spring Security配置导致静态资源无法访问

### 问题描述
配置`SecurityConfig`后，静态HTML文件无法访问，访问`/admin-login.html`时返回403或404错误。

### 核心解决代码

**1. SecurityConfig.java - 放行静态资源**

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(auth -> auth
            // ✅ 关键1：使用Spring Security标准方法放行静态资源
            .requestMatchers(PathRequest.toStaticResources().atCommonLocations()).permitAll()
            
            // ✅ 关键2：明确配置自定义静态路径
            .requestMatchers("/static/**", "/favicon.ico").permitAll()
            
            // ✅ 关键3：放行所有HTML页面
            .requestMatchers(
                "/",
                "/index.html",
                "/admin-login.html",
                "/loan-dashboard.html",
                // ... 其他HTML页面
            ).permitAll()
            
            // API端点需要认证
            .requestMatchers("/api/**").authenticated()
            .anyRequest().permitAll()
        );
    return http.build();
}
```

**2. WebConfig.java - 配置静态资源处理器**

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // ✅ 关键：配置静态资源位置
        registry.addResourceHandler("/**")
                .addResourceLocations(
                    "classpath:/static/", 
                    "classpath:/public/", 
                    "classpath:/META-INF/resources/"
                )
                .resourceChain(false);
        
        // ✅ 明确配置HTML文件访问
        registry.addResourceHandler("*.html")
                .addResourceLocations("classpath:/static/");
        
        // ✅ 配置其他静态资源类型
        registry.addResourceHandler("*.css", "*.js", "*.png", "*.jpg", "*.ico")
                .addResourceLocations("classpath:/static/");
    }
}
```

### 解决要点
- **PathRequest标准方法**：使用`PathRequest.toStaticResources().atCommonLocations()`放行Spring Boot标准静态资源位置
- **明确路径配置**：在SecurityConfig中明确列出需要放行的静态资源路径
- **资源处理器配置**：在WebConfig中正确配置静态资源的处理器和位置
- **优先级顺序**：确保静态资源放行规则在认证规则之前

## 问题3：事务回滚未生效

### 问题描述
在Service方法上添加了`@Transactional`注解，但遇到异常时事务未回滚，导致部分数据已保存、部分数据未保存，数据不一致。

### 核心解决代码

**1. Zongshe1Application.java - 启用事务管理**

```java
@SpringBootApplication
@EnableTransactionManagement  // ✅ 关键：启用声明式事务管理
@EnableScheduling
public class Zongshe1Application {
    public static void main(String[] args) {
        SpringApplication.run(Zongshe1Application.class, args);
    }
}
```

**2. UserServiceImpl.java - 正确配置事务回滚**

```java
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {
    
    @Override
    @Transactional(rollbackFor = Exception.class)  // ✅ 关键：所有异常都回滚
    public Map<String, Object> register(RegisterRequest request) {
        Map<String, Object> result = new HashMap<>();
        
        try {
            // 1. 检查手机号是否已注册
            if (userRepository.existsByPhoneNumber(request.getPhoneNumber())) {
                result.put("success", false);
                result.put("message", "手机号已注册");
                return result;  // 提前返回，不触发回滚
            }
            
            // 2. 创建用户实体
            User user = new User();
            user.setUserId(UUID.randomUUID().toString().replace("-", ""));
            user.setPhoneNumber(request.getPhoneNumber());
            // ... 设置其他属性
            
            // 3. 保存用户
            userRepository.save(user);  // 数据库操作
            
            // 4. 发送短信验证码（如果失败，应该回滚）
            sendSmsVerificationCode(request.getPhoneNumber());
            
            result.put("success", true);
            return result;
            
        } catch (Exception e) {
            // ✅ 关键：捕获异常后重新抛出，触发事务回滚
            log.error("用户注册失败", e);
            throw new RuntimeException("注册失败：" + e.getMessage(), e);
        }
    }
}
```

**3. 事务回滚配置说明**

```java
// ✅ 方式1：所有异常都回滚（推荐用于业务方法）
@Transactional(rollbackFor = Exception.class)
public void businessMethod() {
    // 业务逻辑
    // 任何异常都会触发回滚
}

// ✅ 方式2：默认回滚（只回滚RuntimeException和Error）
@Transactional
public void businessMethod() {
    // 只回滚运行时异常
}

// ✅ 方式3：指定异常类型回滚
@Transactional(rollbackFor = {BusinessException.class, SQLException.class})
public void businessMethod() {
    // 只有指定异常才会回滚
}
```

### 解决要点
- **启用事务管理**：在主启动类添加`@EnableTransactionManagement`
- **配置回滚规则**：使用`rollbackFor = Exception.class`确保所有异常都回滚
- **异常处理**：捕获异常后必须重新抛出，否则事务不会回滚
- **提前返回**：正常业务逻辑的提前返回不会触发回滚，只有异常才会回滚

### 注意事项

1. **默认行为**：`@Transactional`默认只回滚`RuntimeException`和`Error`，不回滚`Exception`
2. **异常必须抛出**：如果异常被catch后没有重新抛出，事务不会回滚
3. **方法调用**：只有通过Spring代理调用的方法才会生效（同类内部调用不生效）
4. **异常类型选择**：根据业务需求选择合适的回滚规则，避免过度回滚

## 总结

这三个问题的解决都遵循了Spring框架的最佳实践：

1. **CORS配置**：统一配置源，避免多配置冲突
2. **静态资源**：使用标准API + 明确路径配置
3. **事务管理**：启用管理 + 正确配置回滚规则 + 正确异常处理

所有解决方案都**代码简洁、易于维护、性能影响小**，符合生产环境使用标准。
